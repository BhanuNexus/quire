# Review: 0.14 opt-in local AI pack (`0.14-local-ai.md`)

Status: proposed (0.14, awaiting owner approval)
Area: architecture review
Code: `apps/quire-ai-engine/src/`, `crates/quire-ai/src/catalog.toml`, `crates/quire-app/src/settings/ai_local.rs`

Reviewer: the 0.14 architect. Read against `0.14-architecture.md` and the code at main ad3216d.
I could not check the Qwen 3.5 layer equations against their sources from this machine; the
review takes them as the designer states them and judges the plan to prove them.

## Verdict: approve with changes

The engineering plan is sound and honest. It reuses what `qwen3.rs` already does for
memory (compact weights, the quantized token table), keeps one form of the recurrence
instead of two, proves the layers three ways (an f64 oracle, a tiny model built through the
real converter, the real file against llama.cpp), keeps the consent gate tight (`pack`,
with old capability keys inert), and stays inside the layering and the frame's memory rows.
It also corrects the frame: the 3,200 MB figure for Qwen3 4B in `catalog.toml` is an
estimate, not a measurement; the frame now says so.

What it lacks is a decision point. By its own numbers the feature may be too slow to ship,
and that is discovered at the end of the plan.

## Blocking issues

**B1. No go/no-go gate on speed.** §3.6 estimates 2–3 minutes before the first word for a
2,000-token Ask prompt with 4B on a four-core laptop, and 6–8 minutes with 9B. T3 measures
real behaviour "before release", after the dialog, onboarding, pins and perf rows exist.
*Fix:* make speed a gate right after step 2 (the forward pass), before steps 4–9. Run the
random-weight 4B and 9B shapes on one named reference laptop and on the build VM, and write
the numbers in `docs/formats/model-catalog.md`. Give the owner a threshold to accept or
change before the round ends; my suggestion: 4B reads at least 10 tokens/s and writes at
least 1.5 tokens/s on four laptop cores, 9B at least half of that. Below it, the pack ships
as "experimental" (today's switch) or waits, and steps 7–9 are not built. Prompt reuse
(step 4) helps agent runs only; it does not help the first Ask.

**B2. A third-party model file needs a provenance check that is not optional.** The GGUFs
come from unsloth, not from Qwen. The plan compares the engine with llama.cpp on the same
file (which proves the engine) and with Qwen's own bf16 weights only "where a machine with
24 GB is free" (which is what proves the file).
*Fix:* the comparison with Qwen's weights is a release condition for every pinned
third-party model file, 4B and 9B, with its threshold fixed before the run and the result
recorded next to the pin. Pin each URL to a commit (`resolve/<commit>/…`), not `main`:
with `main`, a re-upload by the publisher breaks the download for every user until a Quire
release. Say what a person sees when a pinned URL is gone or its hash no longer matches
(one clear message, no retry loop, nothing half-installed), and that the remedy is a point
release with a new pin.

**B3. The pack is wider than the owner's decision.** The brief says: no features in 0.14
except the opt-in local AI, the models are Qwen 3.5 4B and 9B. The design's pack also turns
on OCR, Whisper transcription and a neural embedder, with more pins, a second large model in
memory (Whisper small peaks at 3.6 GB) and a known slow path (question 5: 30 s of audio in
46 s with the smallest model). They are built, but none has shipped.
*Fix:* ask the owner (question 1 below) and build the gate so the answer is cheap: `pack`
enables only the capabilities ticked in the dialog, each with its own key, and the dialog's
rows come from a list that can be shortened. My recommendation: the writing model and OCR
in the pack; voice stays behind `experimental` until its decoder cache is done; the neural
embedder stays unticked, as designed.

**B4. The fallback is named but not real.** §5.2 keeps `qwen3.rs` "as the fallback the frame
asks for" and removes the three Qwen3 rows from the catalog in the same change. If Qwen 3.5
fails B1 or the quality checks, there is then nothing to ship.
*Fix:* decide the branch now and write it down: either "no writing model in 0.14; the pack
is OCR only" or "pin Qwen3 1.7B (`ram_mb` 1,700, measured) as the writing model for this
release". Keep the Qwen3 rows in `catalog.toml`, unpinned (an unpinned row cannot download,
`CatalogFile::is_pinned`), until that decision is made.

## Non-blocking changes

- **macOS free memory.** 8 GB Macs are the commonest 8 GB machines and get only the
  `min_ram_gb` check. Read free and inactive pages the way total memory is read on Windows
  (one system command, behind the existing process rule), or say plainly in the dialog that
  other programs may need to be closed.
- **Free disk before download.** Check that the models folder has the download size plus a
  margin, and say so before starting; a 5.7 GB file that fails at 90% is a poor first run.
- **Perf job weight.** Generating a 2.7 GB random-weight file and holding 3.5 GB in every
  pull request's `perf` job is too heavy. Run the 4B row weekly and on changes under
  `apps/quire-ai-engine/`; 9B weekly.
- **Engine priority.** Minutes of all-core work should run at low priority, as the index
  workers do (`quire-index/src/background.rs`), so typing and indexing stay smooth.
- **Embedders and agent views.** `0.14-agent-index.md` §3.4 shares model-embedder vectors
  between views only if each vector depends on its own passage alone. Add one sentence that
  the pack's embedder pools and normalises per passage and that no cross-passage step
  (centring, whitening) is added.
- **The embedder interface changes under you.** `0.14-index-startup.md` replaces
  `SemanticBuilder` with `set_embedder(Option<Arc<dyn Embedder>>, VectorCache)` and asks for
  f16 vectors in memory. `crates/quire-ai/src/local.rs` and `quire-app/src/ai.rs` must move
  with it; agree who edits them (I suggest index-startup, in its step I2a).
- **Reading progress** ("1,240 of 2,000") is the right honesty. Also show an estimate of
  the wait before the person sends a long question to a slow model.

## Conflicts with the frame and the other designs

1. **Frame §5** called 3,200 MB "measured". Corrected.
2. **Frame §10 risk 9** (fallback): see B4.
3. **Index-startup** (embedder interface, f16): above.
4. **Agent-index** (per-passage normalisation): above.
5. **Memory on 8 GB:** the design agrees with the frame that the index memory row is a
   release condition for offering 4B at 8 GB. Note that `quire-cli mcp` or `serve` running
   beside the app holds a second index; the free-memory check covers it on Linux and
   Windows only.
6. **Build machine:** steps 1–4 compile candle; never beside another candle build.

## Simpler alternatives

- **Ship the writing model only** (B3): fewer pins, one model in memory, no Whisper rule.
- **Qwen3 for this release, Qwen 3.5 when candle has it.** The engine already runs Qwen3
  with measured memory, and no new model code would be needed. It is not what the owner
  chose, and Qwen3 4B does not fit 8 GB machines (its attention cache is 2.25 GiB at 8,192
  tokens against 512 MiB here), so I do not recommend it as the plan; it is the fallback
  of B4.
- **Skip prompt reuse (step 4) in the first cut.** It is a medium step with its own
  correctness risk (restored DeltaNet state). Build it only if B1's numbers pass and agent
  runs are in the pack's first release.

## Questions for the owner

1. What does the pack turn on in 0.14: only the Qwen 3.5 writing model, or also OCR, voice
   transcription and a neural embedder? *Recommendation: the writing model and OCR; voice
   stays experimental; the embedder stays an unticked option.*
2. How slow is too slow? *Recommendation: 4B must read at least 10 tokens/s and write
   1.5 tokens/s on a four-core laptop (9B half of that), measured right after the forward
   pass is built; otherwise the pack stays experimental in 0.14.*
3. If Qwen 3.5 misses that or the quality checks: no writing model in 0.14, or Qwen3 1.7B
   as a stand-in? *Recommendation: no writing model; do not ship a stand-in the owner did
   not choose.*
4. Model files from a third party (unsloth), pinned by hash and checked against Qwen's own
   weights before release? *Recommendation: yes, with that check mandatory; switch to an
   official file when one exists.*
5. Metal on macOS for Qwen 3.5? *Recommendation: CPU only in 0.14.*
6. Suggest 9B on 16 GB machines even though it reads prompts about 2.5× slower?
   *Recommendation: decide from the numbers of question 2; default to 4B if in doubt.*
7. Lite keeps downloading the engine when on-device AI is turned on? *Recommendation: yes.*

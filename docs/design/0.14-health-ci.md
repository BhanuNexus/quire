## What changed

- **The changelog check is scripted, and still a warning.** `packaging/check-changelog.py` (tests: `packaging/test-check-changelog.py`, run in the `packaging` job) flags a pull request that changes source under `crates/` or `apps/` but not `CHANGELOG.md`. Not source: files under `tests/`, `fixtures/` or `testdata/`, and `*.md` (so every `AGENTS.md`). It passes with the label `no-changelog` or from the actor `dependabot[bot]`. It reads the pull request's base and head SHAs (full history). The job is skipped on a push to main; `ci-result` already lists it and counts a skip as passed. Adding the label does not re-run CI: re-run the job. The step has `continue-on-error: true`: the owner decided the check warns and does not block. Removing that line makes it a gate.
- **Tests run with `cargo nextest run --profile ci`** (`.config/nextest.toml`): no retries, a test over 60 s is reported as slow and at 5 minutes is terminated, so a hung test no longer holds the job for its 50 minutes; JUnit goes to `target/nextest/ci/junit.xml` and is uploaded as `junit-<os>`. Doctests, which nextest does not run, run in the next step with `cargo test --doc`. Job names are unchanged. `.config/` counts as "everything" for the pull-request crate selection, like `.cargo/`.
- **`real_servers` fails when it cannot run.** With `CI` set and `QUIRE_SYNC_REAL_SERVERS` unset it panics; `QUIRE_SYNC_REAL_SERVERS=skip` is the explicit opt-out (set in `ci.yml` and in the release's dry-run test step). `real-servers.yml` runs it weekly against moto (S3) and WsgiDAV (WebDAV): the test starts both from a Python venv. MinIO and a real cloud bucket are not covered; a bucket needs credentials only the owner can add as repository secrets, and the test would need a mode that takes an endpoint instead of starting servers.
- **Mutation testing** (`mutants.yml`, `.cargo/mutants.toml`): `cargo mutants --in-diff` on pull requests that touch `quire-markdown`, `quire-import` or `quire-canvas`, advisory (`continue-on-error`, not a required check), and a weekly run of all of `quire-markdown` in 8 shards. The surviving mutants listed in the research are covered by new tests in `table.rs`, `cite.rs` and `scan.rs`.
- **Property tests**: `props.rs` gained properties that `scan_inlines`, `cite::scan` and `table::format_at` finish (on a watchdog thread, so a loop fails the test instead of hanging), return ordered ranges on character boundaries, and that formatting a table twice changes nothing. 256 cases by default; `proptest.yml` runs 50,000 weekly.
- **Fuzzing**: `fuzz/` is a separate crate (own `[workspace]`, also in the root `exclude`) with five targets: `front_matter`, `scan_inlines`, `obsidian_expr`, `sync_wire` (revision and manifest JSON, folder and part names) and `sync_xml` (S3 and WebDAV listings). `fuzz.yml` runs each for 5 minutes weekly on nightly and uploads crashes. The sealed payload of a revision, the folder-mirror reader, the canvas and importer readers and the MCP body are not fuzzed (see `fuzz/README.md`).
- **Ratchet** (`ratchet.yml`, `packaging/ratchet.py`): counts `Result::unwrap_or_default`, wall-clock calls and `std::env::var` in non-test code with clippy's `disallowed_methods` under its own configuration, and fails above the baseline in `packaging/ratchet.toml`. Measured on 69c664f: 187 `unwrap_or_default`, 109 wall-clock calls and 21 `std::env::var` (the plan's 198, 122 and 48 counted tests too, or `Option`). A use under an `#[expect(clippy::disallowed_methods)]` is not counted.

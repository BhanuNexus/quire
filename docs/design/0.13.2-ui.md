# Quire 0.13.2: saves and entry points

The UI team's part of the 0.13.2 data-safety pass: canvas and sketch saves,
embed saves, and the CLI and MCP entry points. No features, no format
changes. Each item says whether it was real, what changed, and what was left.

## 1. Canvas and sketch saves (reliability 6): real, fixed

Confirmed by reading `CanvasSurface::save` and `SketchSurface::save`: all five
parts were true (`dirty = false` after a failed write; unconditional
`write_atomic`; saved only while shown or on drop; no history; no sync nudge).
The report's sixth point (a conflict copy that can't be written still named in
the notice) was already handled for the unreadable-file case (`kept` is
checked) and is unchanged; in the merge-conflict case the `let _ =` write of the
copy is still there, see "Left" below.

Changed (`apps/quire-desktop/src/canvas_ui/{mod,ink}.rs`, `surfaces.rs`):

- Both surfaces save through `quire_app::drawings::save_drawing`, the checked
  write the drawing editor uses: it writes only over the text last read or
  written (`Vault::write_if`), keeps the version before and after in history,
  and nudges sync.
- A failed write leaves `dirty` set, tells the person once ("Couldn't save X:
  why. Your changes are still here; Quire will keep trying."), and retries
  after the autosave delay, not every frame. A later success clears it.
- A change that landed before the watcher reported it: the canvas takes it in
  with the same merge `absorb` already does (`take_in`), and the save happens
  on the next try; the other version is kept in history by `save_drawing`. A
  sketch keeps our drawing and adopts theirs as the new base, with theirs in
  history and a notice.
- `Surface::tick` (another tab shown) and `Surface::close` (tab closed, app
  quits) now save canvases and sketches, as drawings do. A tab whose close
  could not write its edits stays open (`Surface::unsaved`, checked by the
  tab strip's close button).
- `Drop` is only a last resort now: the same compare-and-swap write, no
  history, no nudge.

Left (at the time; see the follow-up below for what changed): other paths of the close (a surface that is `done()` or a duplicate) don't veto the close.

Tests (`canvas_ui/mod.rs`): `a_failed_save_keeps_the_edits_and_tells_the_person`,
`a_save_never_overwrites_a_change_made_elsewhere`,
`edits_are_saved_when_the_tab_is_hidden_or_closed`.

## 2. Notes edited through an embed (reliability 7): real, fixed

`save_hidden` used `vault.write`. It now writes as `Workspace::save` does: a
locked folder through `secure_state::save_locked`, otherwise
`write_bytes_if` against the text last read. On a refused write their version
is kept in history first, then taken in the way a watcher event is (merged if
clean; otherwise the embed keeps its edits, the other version is in history,
and the notice says so). The watcher path (`vault_event`) shares that code and
now also keeps their version in history before keeping ours. Tests in
`nav/embed.rs`.

## 3. A mistyped vault path (polish 1): real, fixed at the entry points

`LocalFs::new` is unchanged (no change in `quire-vault`). New
`quire_mcp::require_folder` (`No folder at <path>. Check the path. To start a
new vault, create the folder first (mkdir …)`, or "is a file, not a folder"),
used by:

- `Server::open_with` (so `mcp`, `mcp serve-http`, `serve`);
- the CLI's `commands::open_vault` and `load` (search, index, notes,
  capture, import, format, agent, ai, prefs, tasks, links and the rest), and
  by `lint`, `tasks` refactors, `remind`, `lock`, `sync` and `serve`, which
  had their own "isn't a folder" text or none.

No CLI command creates a vault except `import --write` (see the follow-up);
the documented way for the others is `mkdir -p`. The desktop's startup already
ignored a last or argument vault that isn't a folder. Its Open a vault window
used to say "It's created if it doesn't exist", so a typo made a vault: it
now says `No folder at …` and the button reads "Make folder and open" for a
folder that isn't there.

Tests: `apps/quire-cli/tests/entry_cli.rs`.

## 4. CLI usage (polish 4, cheap parts): done

- `quire-cli <command> --help` / `-h` (in the first two arguments) and
  `help <command>` print only that command's usage and never open a vault;
  `serve` keeps its longer help.
- A missing argument: `quire-cli search: missing <query>. Run
  `quire-cli search --help` for how to use it.` (the name is taken from the
  command's usage when it has one form, else "a required argument").
- An unknown command: one line, with a "did you mean" within two edits.
- Usage errors exit 2 (a flag set by `arg()`/`unknown_command`); other
  failures exit 1.
- The `\"` in the `search` and `capture` help is fixed; a unit test checks no
  help text has a backslash.

Left: no per-subcommand help (`sync join --help` prints the whole `sync`
usage), `sync`'s 35-line usage, `--json` output, and the rest of item 4.

## 5. MCP errors (polish 6, the wrong ones only): done

- Read-only over HTTP: "This connection can only read. Ask the person for a
  token with the notes:propose scope (…), or approve write access when you
  reconnect"; with `serve --read-only`, it says to restart without it. Stdio
  keeps the `--allow-write` text.
- A tool the connection lacks a permission for: names the permission and
  points to `vault_info`.
- `permission_denied` is built in `write_error` (the `quire-agent` `Display`
  text is unchanged, `acp.rs` has its own): the zone's mode in words, and no
  "write under wiki/".

Left for 0.14: the rest of polish 6 (`inbox_full`, `too_large`, `no_match`,
the server `instructions`), and polish 3 and 5. The unknown-tool text
("Unknown tool x", polish 6's suggestion to change it) was tried and put
back: the recorded 0.8 and 0.9 sessions in `crates/quire-mcp/tests/fixtures`
pin it for old clients, and the brief said to fix only the wrong messages.

## Review follow-up (fix/0132-ui2)

An independent review of the merged branch found one high and several medium
problems in the changes above. Each, in order:

- **U-H1 (high), quit dropped unsaved canvas and sketch edits: real, fixed.**
  When the window is closed, the app now runs `close_all` and the note saves
  again, then lists every surface and note that is still unsaved
  (`Surfaces::unsaved_titles`, `nav::unsaved_after_retry`) in the quit dialog
  (`lock_ui::QuitDialog`, now with a second list): go back, or quit without
  them. Nothing is dropped silently, except that a quit already confirmed (or
  a quit that doesn't go through the window, such as a killed process) can
  still lose them. The failure notice now says "Quire tries again; closing the
  tab or quitting asks you first", which is true.
  `layout_check` covers the dialog (two new samples in `registry.rs`).
- **U-M1 and U-L2, a tab that can't be closed: real, fixed.** `error` no
  longer blocks saving or hides unsaved edits: an unreadable outside change
  with unsaved edits (or with only a sketch unsaved) keeps theirs in history
  and in a copy and leaves the edits visible; `error` is set only when nothing
  is unsaved and clears when a later read parses. A tab whose save keeps
  failing opens a window: "Save a copy as…" (a name the person types; dirty
  sketches are written beside the copy and the copy points at them),
  "Keep open", and "Close without saving" behind a second confirmation.
- **U-M2, the conflict copy written with `let _ =`: real, fixed.** The copy is
  written with `Vault::write_if(…, None, …)` (the vault's normal write, so a
  locked folder encrypts it), tries each numbered name and never overwrites a
  file; theirs goes to history first. If no copy can be written, ours is not
  saved over theirs until one can be (`hold`), and the notice says that.
  History keeping is best-effort (queued); the hold waits for the copy, not for
  history.
- **U-M3, saving into the current vault: real, fixed** by the simpler option:
  `drawings::save_drawing_in` takes the vault, and surfaces pass their own.
  The tab itself still stays open after a vault switch (not changed); its
  saves go to the vault it was opened from. Test: switch vaults with an
  edited canvas.
- **U-M4, `--help` only in the first two arguments: real, fixed.** A
  standalone `--help` or `-h` before a `--` prints that command's usage (the
  long text for `serve`) and runs nothing. `--` is removed before the command
  sees its arguments. `serve help` is help, never a folder.
- **U-M5, `import`: fixed.** `import <source> <vault> --write` makes the vault
  folder (one level, so a missing parent is an error: an unplugged drive is
  not made on the wrong disk). A dry run makes nothing and skips the clash
  check. Every other command still refuses a missing folder. The docs'
  `mkdir -p` lines are the pipeline team's.
- **U-L4: fixed.** The remaining call sites (`lock`, `agent`, `format`,
  `import`, `tags`, `props`, unknown `sync`, `agent` and `mcp token`
  subcommands) now return one line and exit 2. Changed script-facing
  behaviour the review lists (exit 2 for usage errors, exit 1 for a missing
  folder, new `No folder at` texts) is as described there.
- **U-L5, Make folder and open: fixed.** `~` is expanded; a full path is
  required; the button is offered only when the folder above exists; the full
  path is shown; the disk is looked at when the text changes (and every two
  seconds), not every frame. `vault_choice` has a test.
- **U-L6, `require_folder`: fixed.** It reports the real error for a missing
  mount, a permission error or a dangling link, and suggests `mkdir` only when
  the folder above exists.
- **U-L1, U-L3, U-L13: fixed.** The `Drop` fallback puts back a deleted file
  as `save_drawing` does (canvas and sketch); a hidden tab whose save failed
  asks for a repaint (every ~2.4 s for canvases, 2 s for sketches); the
  quit path saves notes again so a merge left unwritten by a refused save is
  written, and asks about what still isn't.

Not changed: the tab-close path for a surface that is `done()` or a duplicate
doesn't veto the close; `Surface::save_copy_as` doesn't exist for other
surfaces (they report "can't be saved as a copy"); only a quit through the
window is asked about.

## Final review follow-up (fix/0132-ui3)

- **F-M1, the drawing editor missed the canvas fixes: real, fixed.**
  `DrawingEditor` now has `Surface::unsaved()` (its edits aren't written),
  `discard()` and `save_copy_as()` (a copy must keep a drawing's ending;
  `suggested_copy` keeps `.excalidraw.md` / `.excalidraw` / `.json`). So it is
  listed in the quit dialog, and its tab, when a close could not write its
  edits, stays open and gets the stuck-tab window ("Save a copy as…", "Close
  without saving"). `done()` is false while edits are unsaved. It saves, reads,
  renames and copies through the vault it was opened from (`save_drawing_in`,
  `read_drawing_in`, `copy_path_in`), not whatever vault is current. The "(unsaved
  edits n)" copy (also in `Drop`) never overwrites a file and its result is
  checked: on failure the edits stay in the open tab (`close`) or are reported on
  stderr (`Drop`). "Close" on a drawing deleted elsewhere keeps the edits in a
  copy first. Tests: `a_drawing_that_cannot_be_written_is_listed_for_the_quit_dialog`,
  `a_drawing_saves_into_its_own_vault_after_a_vault_switch`.
- **Every `Surface` and other owner of editable state:**
  - `CanvasSurface`, `SketchSurface`, `DrawingEditor`: `unsaved()`, quit dialog,
    stuck-tab window, own-vault saves.
  - `PdfSurface`: highlights and comments are written at once through
    `pdf_state::write_note` into the PDF's annotation note, an open note
    document, covered by the note path (`unsaved_after_retry`); a comment draft is
    saved by its button.
  - `BaseSurface` and `HomeSurface`: read-only (a base's "convert" is an
    action on the workspace). `LockedSurface`: holds a passphrase draft only.
    `SystemViewer`: unused.
  - Boards, task views, the agent panel and the inbox: change notes or files
    through workspace actions (note documents, covered by the note path, or an
    immediate checked vault write that reports its error). They hold no unsaved
    state of their own.
- **Auto-lock:** the idle lock waits for a drawing with unsaved edits
  (`CanvasState::unsaved_in`). Canvases and sketches don't register there; a
  folder with a canvas or sketch that can't be saved is not held unlocked. Left
  as it is.
- **F-L4, `--` didn't protect words: real, fixed, once.** `main` records where
  the literal operands start; every command reads flags and their values only
  from `commands::options` (`has_flag`, `flag_value`, `words_without`,
  `is_option`). After the first `--` nothing is a flag, so `replace <vault> --
  --write done` is a dry run, and `capture <vault> -- --url x` captures the text.
  `--help` before the `--` still prints help. Tests (`tests/entry_cli.rs`):
  `replace`, `capture`, `search`, and `tags` (with subcommands).

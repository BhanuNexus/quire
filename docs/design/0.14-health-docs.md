# Quire 0.14 health: instructions and checks

Status: current
Area: agent instructions, docs, CI and packaging checks
Code: `AGENTS.md`, `docs/howto.md`, `ARCHITECTURE.md`, `packaging/check-layering.py`, `packaging/check-design-notes.sh`, `packaging/affected-crates.py`, `deny.toml`, `.github/workflows/`, `.claude/skills/`

The instructions-and-checks part of the codebase-health pass. No Rust was built for it and no user-visible behaviour changed. Items are numbered as in the pass's plan.

## What changed

- **Item 2, wrong instructions.** The "frozen" headers of `crates/quire-app/src/features.rs`, `apps/quire-desktop/src/registry.rs` and `apps/quire-cli/src/commands/mod.rs` now say what is true (comment lines only). `crates/quire-sync/src/lib.rs` points at `docs/formats/sync-protocol.md`, `0.12-sync.md` and `0.13-sync.md`. `ARCHITECTURE.md` lost the identifiers and paths that no longer exist, has a note that §9 to §12 are history (§9's plugin plan is marked dropped, P7), and `RELEASING.md` says the engine pin file is generated and git-ignored.
- **Item 4, `deny.toml` `[bans]`.** Nine third-party bans (egui, eframe, rfd, axum, tokio, ureq, typst, candle-core, rusqlite) with wrappers. `cargo deny check bans` passes; removing `quire-import` from the `ureq` wrappers fails it with `error[banned]` (tested on a copy). `quire-base` is already a `ureq` wrapper, so cargo-deny prints an `unused-wrapper` warning until that crate exists.
- **Item 5, layering.** The layer table is the crate table in `ARCHITECTURE.md` §3 (a `Layer` column and the named same-layer edges under it); `packaging/check-layering.py` reads it and compares it with `cargo metadata --no-deps --offline`. Tests with made-up metadata: `packaging/test-check-layering.py`. CI's `packaging` job runs both.
  - It fails on a missing or extra row, a wrong path, an edge to the same or a higher layer (except the named ones), a library crate other than `quire-app` turning on another crate's non-default feature, and any difference in the "Depends on" column.
  - Two tolerances, each with a comment in the script: `quire-vault → quire-sync` (to be removed by the foundations work) is allowed and optional in the table; `quire-base` may be listed before it exists, and edges to it are left out of the comparison until it is removed from `PLANNED`.
  - One feature exception today: `quire-assistant → quire-ai` with `client` (`FEATURE_ALLOW`).
- **Item 10, `AGENTS.md`.** 100 lines, from 116: the crate table, the collision list and the release paragraph are gone; "Where to start" and "Rules learned the hard way" (each `[test]`, `[lint]` or `[review only]`) are new. No `CLAUDE.md`.
- **Item 12, `docs/howto.md`.** Six jobs, checked against the code. Lines that depend on the other 0.14 teams are marked.
- **Item 13, design notes.** Every note has `Status`, `Area` and, if current, `Code`; `packaging/check-design-notes.sh` blocks in CI. Free-text status lines were kept as `Origin:`. Five citations of files outside the repository were reworded. `0.9.md` has a reading banner.
- **Item 15, changelog.** One wording in `AGENTS.md`, `CONTRIBUTING.md` and the pull request template: one bullet, at most two sentences, what a person sees. CI warns (never fails) when a pull request changes `crates/` or `apps/` without a new `CHANGELOG.md` line, unless it carries `no-changelog`.
- **Item 16, skills.** `.claude/skills/release` (not model-invocable) and `.claude/skills/review-change`.
- **Item 25, CI time.** `SYNC_SEEDS=30` on the macOS and Windows test legs, 150 on Linux (`folder_sync.rs` reads it with a default of 150).
- **Owner request, CI that does less.** See below.

## CI after this change

- **Pull request, docs only** (Markdown, `docs/`, `.claude/`, `LICENSE`, issue templates): `changes`, `changelog`, `workflows`, `packaging`, `typos`, `deny`, `dco`. `lint`, `test`, `test-features` and `perf` are skipped.
- **Pull request, one crate:** `lint` (whole workspace), `test` on four operating systems with `cargo test -p` for the crate and its dependents, `perf`; `test-features` only if the Lite apps, `quire-pdf` or `quire-cli` are among them (each step by its own crate).
- **Push to main:** everything, as before (`--workspace`).
- **Tag:** `check` runs `packaging/check-ci-green.sh` for the tagged commit instead of `cargo test --workspace`. A dry run from a branch still runs the tests.
- `affected-crates.py` counts changed crates plus dependents (dev-dependencies too), a change under `tests/`, `benches/` or `examples/` for its crate alone, files a crate includes or reads from outside its folder for that crate, and the root `Cargo.toml`, `Cargo.lock`, `rust-toolchain*`, `.cargo/` and the workflow files for everything.
- `ci-result` is one job that is green when no job failed; require it instead of the `test (<os>)` names, because a skipped matrix job reports one check called `test`.

# Quire 0.13.1: dependencies

Status: record
Area: dependencies

A record of a pass; not a description of today's code.

The hardening pass adds no features. This note covers the dependency team's part: vulnerabilities, unmaintained crates, the open Dependabot updates, unused dependencies, and keeping it from regressing. Measured 2026-11-15 on `hard/deps`.

## 1. Vulnerabilities

| Advisory | Crate | Result |
|---|---|---|
| RUSTSEC-2026-0533 (mutation XSS through SVG and MathML) | ammonia 4.2.4 | **Fixed**: 4.2.5. Regression test `sanitize::tests::mutation_xss_in_svg_and_mathml_is_inert_in_every_html_output` runs the advisory's kind of payload (`svg`/`math`/`foreignObject`/`annotation-xml`/`mglyph`/`style`/`xmp`/`noscript`/CDATA, and a second cleaning pass) through every output the hostile-note test covers: publish and serve (`render_note`), Copy as HTML (with and without a vault), `quire-cli export`, and File → Export as HTML. The test's `assert_inert` now ignores text inside quoted attribute values (the cleaner escapes it; it is text, not an attribute). |
| async-executor 1.14.0 yanked | | **Fixed**: 1.14.1. |
| RUSTSEC-2026-0194, -0195 (quick-xml 0.38: quadratic time, unbounded allocation) | via typst-library → hayagriva → citationberg | **Documented, ignored in `deny.toml`**. No fix exists: typst 0.15.1, hayagriva 0.10.1 and citationberg 0.7.0 are the newest releases (crates.io, 2026-11-15), and 0.41+ needs a new citationberg. Quire does not reach the parser with user input: the PDF export gives Typst a style *name* from `BIB_STYLES` (embedded APA, Chicago author-date, IEEE), the bibliography file is always the generated `/references.bib` (BibTeX, parsed by biblatex), and user CSL JSON is read by Quire's own code. Typst's `CslStyle::from_xml` is only reached for a `.csl` file path or inline bytes given to `bibliography(style: …)`, which Quire never writes, and note text cannot write Typst code that does: every piece of note text is escaped for Typst markup (`escape_markup`) or passed as a string literal (`typst_string`); the one place Typst code is evaluated from note text is math (`eval(…, mode: "math")` in `mitex.typ`), where mitex escapes each `#` from the note as `\#` (checked on a corpus of hostile formulas by `formula_text_never_becomes_typst_code`; `\iftypst`, the raw-Typst escape hatch, is refused). The Typst world serves only files Quire adds (images checked as images, diagram SVGs, the generated `references.bib`, Quire's own `.typ` helpers), none of them a CSL file. |
| RUSTSEC-2026-0235 (rkyv 0.7 out-of-bounds read) | via mitex-spec | **Documented, ignored**. mitex 0.2.4 is the newest. The first version of this note said mitex never calls `mitex-spec`'s `from_bytes`; **that was wrong**. `mitex_spec_gen::DEFAULT_SPEC` calls it once, on first use, on the `default.rkyv` that mitex's build embeds (`include_bytes!`), and `mitex::convert_math(input, None)` takes that default (`converter.rs`, `spec.unwrap_or_else(|| DEFAULT_SPEC.clone())`). Quire always passes `None` (`quire-typeset/src/math.rs`), so the only archive rkyv reads is that fixed build-time file, with validation (`check_archived_root`); no note, file or network byte reaches it. The advisory stays ignored on that ground. mitex-spec's `rkyv` features are on by default with no way to switch them off from the parents. Revisit when mitex moves to rkyv 0.8. |

`cargo audit` has no way to read `deny.toml`, so it still lists these three; `cargo deny check` is clean (advisories, bans, licenses, sources).

## 2. Unmaintained crates

All stay documented in `deny.toml` with the chain that pulls them in; none can be removed from Quire's side, because every parent is already at its newest release or is not ours:

- `bincode` 1, `yaml-rust`: syntect 5.3.0 (newest) via two-face 0.4.5 via typst-library. two-face 0.5 exists but typst-library pins 0.4. Syntax definitions are embedded at build time; no user YAML reaches `yaml-rust`.
- `unsafe-libyaml` via `serde_yaml` via hayagriva (YAML bibliographies are not offered by Quire).
- `fxhash` via mitex-lexer; `paste` via biblatex; `rustybuzz` via krilla; `ttf-parser` via fontdb and others; all in the Typst stack.
- `zvariant`, `zbus_names`, `zvariant_derive`: accesskit_unix (eframe) still uses zbus 5; notify-rust 4.19 now brings zbus 6, which clears the same crates there. Clears completely when accesskit moves to zbus 6.

## 3. Updates applied (Dependabot PRs untouched)

- #66 typos 1.52.2, #54/#53 codeql-action 4.39.3: SHA-pinned with the version comment.
- #60 resvg 0.49, #58 skrifa 0.49, #57 hayro (and hayro-interpret) 0.8: **applied first, then rolled back** to resvg 0.47, hayro/hayro-interpret 0.7 and skrifa 0.44 (what 0.13.0 had). Typst 0.15 pins hayro 0.7 and resvg/usvg 0.47, so the bumps put two copies of the PDF and SVG stacks in the full edition, and the release dry run measured it at 77 MiB against the 74 MiB budget. Dependabot ignores hayro, hayro-interpret, resvg and usvg until Typst moves (`.github/dependabot.yml`). skrifa 0.44 is the version `egui`/`epaint` 0.37 use, so it leaves two copies in the tree (0.42 under hayro-interpret 0.7, 0.44) instead of three with 0.49 (0.42, 0.44, 0.49).
- #59 rten 0.27: **applied as rten 0.28 together with ocrs 0.14.** ocrs 0.13.1 takes `rten::Model` from rten 0.26, so rten 0.27 alone does not compile (and would carry two rten copies); ocrs 0.14 is built on rten 0.28. The catalog's models are `.onnx` files (rten 0.27 turned the old `.rten` format off by default; ONNX is the default and is what Quire downloads), so no model or `catalog.toml` change.
- #65 group (notify 8.2.2, ureq, the deflate crate, notify-rust 4.19, zip 9.6) and `cargo update` for every other semver-compatible crate (57 packages). notify 8.2.2 needs Rust 1.88; the repo's toolchain is 1.97, MSRV unchanged.

Code that had to change for hayro 0.8 was reverted with the bump; `crates/quire-pdf` and `apps/quire-ai-engine/src/models.rs` use the 0.7 API again (`RenderSettings` with the scale, `take_unpremultiplied`). `cargo test -p quire-pdf --features render` passes, including the gold-text and reading-order tests.

## 6. Keeping it from regressing

- CI's `deny` job runs `check advisories bans licenses sources`, so a new advisory fails it whenever CI runs (push and pull request). It has no schedule, so an advisory published between pushes shows on the next one; a weekly scheduled run would need the CI workflow to gate its other jobs.
- `cargo machete` is not added: it needs a pinned third-party action or a `cargo install`, and I could not verify an action SHA here. The five hits are fixed; run `cargo machete` by hand.
- `.github/dependabot.yml`: separate groups for the rendering crates (`resvg`, `hayro*`, `skrifa`, `typst*`, ...) and the model crates (`rten*`, `ocrs`, `candle-*`), the small `minor-and-patch` group excludes them, and the open-PR limit goes from 5 to 10, so a few heavy PRs cannot starve the rest. Security updates have a limit of their own.

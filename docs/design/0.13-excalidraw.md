# Quire 0.13: editing Excalidraw drawings

Quire showed Excalidraw drawings as pictures since 0.10 (§4 of
[0.10-human.md](0.10-human.md)). 0.13 edits them: `.excalidraw` files and
the Obsidian Excalidraw plugin's `.excalidraw.md` notes, in an editor tab,
with the files staying fully readable by Excalidraw and the plugin.
Format: [../formats/excalidraw.md](../formats/excalidraw.md).

## 1. Format fidelity first (`quire_canvas::ojson`, `quire_canvas::drawing`)

* **Ordered JSON** (`ojson`). Elements are kept as JSON objects with their
  keys in order and their numbers as written, not as Rust structs. Every
  field Quire doesn't know (a newer Excalidraw's, `customData`, a type
  Quire doesn't draw) stays, in its place. The writer is
  `JSON.stringify`'s (indent detected from the file, the same escapes and
  JavaScript's number forms), so an element that isn't edited is written
  back byte for byte, and a saved file differs from the old one only in
  the edited elements' lines.
  * Why not `serde_json`: its `preserve_order` feature would change map
    order for every crate in the workspace (features unify), and its
    numbers would lose their text (`100` read as a float writes `100.0`).
    The reader is about 250 lines, depth-limited (200), and tested against
    `serde_json` for values.
* **The file** (`Drawing`). A `.excalidraw` is the JSON document; a note
  is split into its own text, `# Excalidraw Data`, its `##` sections, the
  `%%` lines and the fenced drawing block. Saving puts back what was read
  and replaces only what changed: the block when the scene changed (in its
  own encoding), `## Text Elements` and `## Element Links` when a text or a
  link changed, new lines under `## Embedded Files`.
  * **Round-trip rule**: open then save without edits writes nothing; the
    text it would write is byte-identical to the file (tested on every
    fixture, and the re-encoded JSON and the re-compressed block are also
    byte-identical to the originals).
* **LZ-string**: no crate. The decompressor was already ours (0.10, memory
  bounded); the compressor (once a test helper) moved into the library: a
  port of lz-string 1.5.0's `_compress`, checked against the library's
  reference output and round-tripped through the decompressor on random
  texts. Chunked as the plugin does (256 characters, blank line between).
* **Edits** (`Drawing::*`): add, erase (with bound text; arrows let go),
  translate (bound text follows, bound arrows' ends move to the shape's
  outline, an arrow moved alone lets go), resize (shapes; lines and
  freehand scale their points; text scales its font), rotate (about the
  element's or the selection's centre), set a field, duplicate (groups,
  bound text and bindings copied together, new ids and seeds), group,
  ungroup, z-order, align, lock, text (with measured size), bind, pictures,
  copy and paste (Excalidraw's clipboard JSON).
  * **Excalidraw's rules**: each edit is Excalidraw's `mutateElement`:
    `version + 1`, a new random `versionNonce`, `updated` = now; `seed`
    kept. New elements have `newElement`'s fields. Fractional indices are
    kept valid with a port of `fractional-indexing`'s `generateKeyBetween`
    (and `syncInvalidIndices` after a reorder); drawings without indices
    (before Excalidraw 0.17) get none. Text in a note gets an 8-character
    id (the plugin's), other elements 21 (nanoid's length and alphabet).
  * **Undo** is a stack of states; a state is the elements as `Arc`s, so a
    step costs a pointer per element, and an edit copies only the
    elements it changes (`Arc::make_mut`).

## 2. The editor (`apps/quire-desktop/src/drawing_edit`)

* A surface, like the canvas. `.excalidraw` files open in it from the
  file list; a drawing note opened as a note (from anywhere: quick open,
  a link, the file list) opens in it instead, its Markdown tab saved and
  closed, so only one thing writes the file. "Markdown" in its toolbar
  shows the note as Markdown for the rest of the session (with an
  "Edit drawing" button above it).
* **Tools** (Excalidraw's keys): hand H, select V/1, rectangle R/2,
  diamond D/3, ellipse O/4, arrow A/5, line L/6, draw P/X/7, text T/8,
  picture 9, eraser E/0. Select moves, resizes (eight handles, rotated
  with the element; Shift keeps proportions), rotates (the handle above;
  Shift: 15° steps), marquee-selects, Alt+drag copies; two-point arrows and
  lines show their ends to drag. A shape tool draws one shape and goes
  back to select (Excalidraw's default). Double-click: edit a text, type in
  a shape (bound text, centred), or a new text on empty canvas.
* **Arrows bind** at both ends to the shape under them (rectangle,
  ellipse, diamond, picture, text, frame) when drawn or when an end is
  dragged onto one; dragging an end off lets go. Lines and arrows are two
  points: Excalidraw's multi-point lines are kept and drawn, not made.
* **Style panel** (right, toggles): stroke and background colours
  (Excalidraw's palette), fill style, stroke width and style, sloppiness,
  edges, arrowheads, font (hand-drawn, normal, code), size, alignment,
  opacity, layers, align, duplicate, delete, group, ungroup, lock, link.
  A change applies to the selection and becomes the default for new
  elements, as in Excalidraw.
* **Links**: an element's `link` (`[[Note]]`, `[[Note#Heading]]`, a
  file, a web address) shows a ↗ badge; clicking it, or Ctrl+clicking the
  element, opens it. Texts with `[[links]]` show the link text (or alias)
  and set the element's link, as the plugin does.
* **Index and backlinks**: a drawing note's `## Text Elements` and
  `## Element Links` are Markdown, so the vault index finds their links:
  the drawing shows in the target's backlinks (tested). `.excalidraw`
  files aren't notes and aren't indexed (as before).
* **Commands** (no default keys): "New drawing (Excalidraw)" makes
  `Drawing <date> <time>.excalidraw.md` in the active note's folder (the
  plugin's form and name) and opens it; "Embed a new drawing in this
  note" also writes `![[Drawing ….excalidraw]]` at the caret. An embedded
  drawing shows as its picture in the note; clicking the picture opens the
  editor. After a save, embeds of the drawing redraw.
* **Keys** with modifiers: Ctrl+Z, Ctrl+Shift+Z / Ctrl+Y, Ctrl+A,
  Ctrl+D duplicate, Ctrl+Shift+L lock, Ctrl+] / Ctrl+[ forward/backward,
  Ctrl+Shift+arrows align, Ctrl+0 100 %, Shift+1 fit, Ctrl+' grid, arrows
  nudge (Shift: 5), Delete, Enter edits text, Escape. Copy, cut and paste
  are the system's.
  * **Left out, because Quire uses them**: Ctrl+G group (graph view),
    Ctrl+Shift+[ (fold), so also Ctrl+Shift+G and Ctrl+Shift+] for
    symmetry; Ctrl+K link (command palette); Ctrl+= / Ctrl+- (Quire's
    zoom). Group, ungroup, front and back are in the panel. Zoom is
    Ctrl+scroll or pinch.
  * The test `keys_dont_conflict_with_quires` runs every editor key
    through Quire's conflict checker (`Keymap::conflicts`, all three
    platforms): none is taken by a command that runs while a surface has
    focus (Edit/Format/Review commands yield to it), none is reserved.

## 3. Saving (`quire_app::drawings::save_drawing`)

* **Checked write**: `Vault::write_if(path, base, text)`: written only if
  the file still holds the text the editor last read or wrote (in one
  step against every other write in the process). If not, nothing is
  written: the editor holds a conflict and offers **Keep mine** (theirs
  goes to `<name> (changed elsewhere).excalidraw…`, then ours is saved) or
  **Take theirs** (ours goes to `<name> (my edits)…`, theirs is shown).
  Nothing is overwritten silently; nothing is lost.
* **Changes elsewhere** reach the editor through the vault watcher
  (`canvas_state::vault_event` counts changes to drawings, locked ones by
  their plain name): with no edits here it reloads; with edits here it is
  a conflict (above). Drawings are never merged line by line: a text merge
  of a compressed block, or of JSON, can make a file no one can read.
* **Autosave** 0.6 s after the last edit (not during a drag or while
  typing), and on closing the tab or quitting (`Drop`, through the same
  checked write; if that fails, the edits go to `<name> (unsaved edits
  n)…`). A failed save says so once and is tried again every 10 s.
* **History**: the version before the first edit and each saved version
  go to version history (`HistoryWriter`, off the UI thread), and a change
  found elsewhere is kept as a version too.
* **The encoding is kept**: compressed stays compressed, plain stays plain,
  JSON keeps its indent.
* **Locked folders** (0.11, 0.12): `Vault::read` and `write_if` decrypt
  and encrypt; history snapshots of a locked file are sealed; copies made
  on a conflict are in the same folder, so encrypted too. The editor
  holds the drawing only in memory. Embeds of a locked drawing are drawn
  from memory (`locked_media`, as a PNG under `bytes://quire-locked/…`) and
  forgotten when the folder locks. While the folder is locked the editor
  says so and edits nothing. Tested by
  `secure_state::tests::drawings_in_locked_folders`: a drawing note and a
  `.excalidraw` file edited and saved, a copy written, history flushed,
  then every file under the vault (gzip opened) is scanned for the
  marker text: none.

## 4. Drawing (`drawing_edit/paint.rs`)

* **Style: clean, not hand-drawn.** Shapes are drawn with straight lines
  and true curves, whatever their `roughness` (which is kept, set in the
  panel, and drawn by Excalidraw as before). Hachure and cross-hatch fills
  are drawn flat and lighter; dashed and dotted strokes as such; freehand
  strokes as lines (not perfect-freehand outlines). Fonts: Quire's own
  (Inter for hand-drawn and normal, JetBrains Mono for code), so text
  measures a little differently from Excalidraw's fonts; Excalidraw
  measures text again when it opens the file.
* **Only what's in view** is drawn: each element's box (cached) is tested
  against the view.
* **Tessellation is cached**: an element's paths are tessellated once into
  a mesh, kept per (`version`, `versionNonce`) and zoom; a frame only
  copies the meshes in view with a translation. While the zoom changes,
  meshes are scaled; 150 ms after it rests they are made again at the new
  zoom (sharp lines). Concave fills (hand-drawn closed lines) are ear-clipped.
* **Measured**: `two_thousand_elements_stay_smooth` (2,000 elements:
  rectangles, ellipses, diamonds, arrows, 40-point freehand strokes and
  texts): at 100 % only those in view are drawn, a frame that changes
  nothing tessellates nothing, and panning tessellates nothing. With all
  2,000 in view, a frame took **15.8 ms in a debug build** on this machine
  (the test's bound is 100 ms, for slow CI runners).
* **Nothing before the first frame**: the editor exists only once a
  drawing is opened; no new start-up work, no new crate.

## 5. Tests

* `quire_canvas::drawing::tests`: the round-trip corpus (8 fixtures:
  Excalidraw 0.18 with every element type, bindings, frames, groups,
  `customData`, an unknown type, a deleted element; a pre-0.17 file
  without indices; plugin notes compressed, plain and commented-out;
  the 0.10 fixtures); an edit changes only its element's lines; Excalidraw's
  edit rules; fractional keys; z-order; bindings and bound text; duplicate,
  group, align, lock, paste; resize and rotate; **property tests**: random
  edit sequences on every fixture, then undo all gives the exact state
  and the exact bytes, redo all gives the edited state; random edits keep
  ids unique, versions growing, indices ordered, bindings pointing at
  elements that exist, and the file readable back to the same elements.
* `quire_canvas::ojson::tests`: write-back, JavaScript numbers, bad and
  deep input, agreement with `serde_json`.
* `quire_app::drawings::tests`: checked save, history, backlinks from a
  drawing note, conflict detection, new and embedded drawings.
* `secure_state::tests::drawings_in_locked_folders` (above).
* `drawing_edit::tests` (driven by pointer and key events): drawing a
  shape, autosave keeps every field, undo saves back to the original

  routed to the editor; the editor's layout at three window sizes, light

## 6. Deferred, and why

* **Hand-drawn rendering** (rough.js's wobble, hachure lines,
  perfect-freehand strokes): a port of rough.js is large; the clean style
  shows the same drawing, and the files keep `roughness` and `seed` so
  Excalidraw draws them as before.
* **Excalidraw's fonts** (Excalifont, Virgil, Nunito…): their licences
  allow bundling, but they add about 1 MB to both editions for one
  feature; Quire's fonts are used and the choice is kept in the file.
* **Multi-point lines, curved arrows, elbow arrows, arrow labels**: kept
  and drawn, not made or edited point by point (two-point arrows and
  lines are).
* **Frames** (making, naming, clipping), **libraries**, **laser
  pointer**, **collaboration**, **Mermaid to Excalidraw**, **embeddables**
  (web pages in a drawing), **LaTeX equations**, **crop**, **flip**,
  **text wrapping inside shapes** (bound text is centred, not wrapped),
  **eyedropper and custom colours**: kept in files, not edited.
* **Dark mode for the canvas**: the drawing's own background is shown, as
  Excalidraw's light theme; the editor around it follows Quire's theme.
* **The preview pane and canvas cards** show drawings as pictures; only
  the editor's inline picture opens the drawing editor on a click.
* **`.excalidraw` files in the index**: they aren't notes; their links
  aren't backlinks (a drawing note's are).
* **The Obsidian plugin's scripts, `## Text Elements` as the source of
  the texts** (the plugin reads texts from that section when they differ
  from the JSON): Quire takes the JSON's texts and writes both.

## 7. Checked by hand

On Xvfb, dark and light themes, in a vault holding the fixtures: a note
embedding a compressed drawing note shows its picture and the drawing's
backlinks; clicking the picture opens the editor; a rectangle, an arrow
from it to the picture (bound at both ends), a text typed with
`[[Meeting notes]]` (shown as "See Meeting notes", with a ↗ badge) and a
freehand stroke were drawn; the file on disk kept the note's own text,
stayed compressed and got the new `^id` line and element link; clicking a
badge opened "Meeting notes" at its heading, whose backlinks list the
drawing; back in the note, the embed showed the edits. The Excalidraw
0.18 fixture showed its frame, bound label, dashed ellipse, arrowheads,
dotted line, freehand stroke, picture and embeddable; the style panel for
an arrow showed its arrowheads. Opening the drawing note from the file
list opened the editor.

Fixed after looking: tool icons that the bundled fonts don't have
(rectangle, line, pen, undo) were boxes; the panel's rows didn't wrap at
its width; the link field kept an old value after typing a link.

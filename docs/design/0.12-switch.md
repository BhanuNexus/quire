# Quire 0.12: switching tools

Status: built on `feat/0.12-switch`. Formats:
[lint](../formats/lint-format.md), [home](../formats/home.md),
[import records](../formats/import-record.md); user guide:
[import](../import.md).

## Why

Three plugin jobs that Obsidian users install first, and that Quire lacked,
are what keep people from switching: importing (Importer, +118k downloads in
30 days), tidying notes (Linter, +100k) and a start page (Homepage, Hearth,
Apex Dashboard: about +97k together). The November market research lists all
three as small, low-risk and for humans. They share a theme: *a note you bring
in, or touch, is never harmed*. So every one of them is previewed, bounded and
undoable.

## 1. Importer

**What existed:** Logseq, Notion, Bear, Evernote and Markdown, behind a one-
screen dialog that read the export on the UI thread, applied it and could not
undo it.

**What changed.** The dialog is a five-step wizard (source, preview, folder,
import, report). Reading, finding name clashes and writing all run on threads
and report progress. `quire_app::import_run` writes the plan, sets file times,
makes a history snapshot per note with provenance "Imported (Source)", and
writes a record of what it created.

**Undo is a record, not a folder trash.** Moving the target folder to the trash
would also trash notes the user added to it afterwards (and the default folder
may already exist). The record lists every file with the hash it wrote; undo
trashes only files that still have that hash. An edited file stays and is
named. The agent ledger's revert was not reused: it reverts by snapshot
ranges and would need one agent batch per import, which would show up as agent
activity.

**Which sources, and why those.** Chosen by how often people ask to leave the
app and how well the export is documented:

| Added | Reason |
|---|---|
| Roam Research JSON | the standing request in every PKM forum; one documented JSON file; its block tree maps to nested lists |
| Google Keep (Takeout) | the largest quick-notes user base; Takeout gives one JSON and its media per note |
| Joplin (`.jex`, RAW) | Joplin's conflict and sync problems are what the market research shows users leaving over; `.jex` is a tar of Markdown with metadata |
| Day One JSON | the leading journal app; entries become daily notes |
| HTML folder | one importer for Apple Notes, OneNote and Evernote-less web clippings: their exports are HTML, and converting HTML is the common need |

Deferred, and why: Apple Notes directly (the database format isn't
documented and changes between macOS releases; the HTML route works),
OneNote `.docx`/`.one` (needs a Word-document reader), CSV and Airtable
(tables are a different job: a column mapping step), Tomboy (small), Craft
(its Markdown export already imports as Markdown).

**Hostile archives.** The tree loader (`tree.rs`) is the only reader of the
export, so the rules live in one place: paths are cleaned and refused if
they leave the root, links are skipped, hidden folders and device names are
skipped, file count, total size, single-file size, depth and name length are
bounded, a high compression ratio is a bomb, and text is decoded rather than
trusted to be UTF-8. Each importer converts text only and never executes
anything. Fixtures cover traversal, absolute and drive paths, symlinks
and hard links in tar, nesting, bombs, oversized and empty exports, bad
encodings, and malformed JSON for every source that reads JSON.

## 2. Linter

**Where it lives.** `quire_markdown::linter`: a pure function from text and
options to text, with no files and no clock. Quire's other crates don't need
a new dependency, and the CLI, the desktop and tests call the same code.

**Safety net instead of trust.** Each rule is a text-to-text function. After
every rule the result is compared with its input by a *signature*: the
parser's events with whitespace squeezed (and code, math, HTML and front
matter compared exactly). A rule whose result changes the signature is undone
and named in `Outcome::reverted`; the other rules still run. A bug in one
rule can therefore make the linter do less, never change what a note says.
Property tests (4000 generated notes) check this, idempotence, that code
blocks and HTML are untouched, that CRLF notes stay CRLF, and that front
matter pulldown can't read is left alone.

**Line endings.** "Keep" is the default and means every line keeps its own
ending. Converting is a whole-file operation and the only rule that changes
bytes on every line, so it is its own option and its signature check ignores
line endings.

**Settings.** `[lint.format]` in `vault.toml`. The agent vault check already
owns flat keys in `[lint]` (`exclude`, a level per check); a subtable keeps
both and a vault written by either reads in the other. The desktop reads and
writes the section with the check's keys passed through untouched.

**Running it.**
- *This note* (Tidy this note): one `replace_minimally` edit, so one undo step.
- *On save* (off by default): only the explicit Save command, not autosave:
  autosave fires while typing and would move the cursor.
- *A folder*: read and tidied on a thread; a dialog shows each changed note
  with its diff and lets you untick notes; writing goes through the safe
  write path (`write_note_with_history`: a version in history, atomic write,
  a check that the note is still what the plan read) in chunks of 20 notes,
  so the window stays alive. A note with unsaved edits or one changed since
  the plan is left alone. The notes are one batch in the activity list, and
  **Undo** reuses the batch ledger the tag-rename uses.
- `quire-cli format <vault> [note-or-folder] [--write]`: the same, a diff
  first.

A note opts out with `lint: false` in its front matter; excluded folders are
left alone on save and in folder runs.

## 3. Home

**A surface, not a note.** It has no file, so it can't be edited into
something the vault stores. It is a tab beside the notes, like a `.base`,
named `Home`. `[home]` in `vault.toml` lists sections, their order and their
settings, so a vault shared between devices has the same Home.

**Cost.** Home reads nothing until it is the tab in front, and then not on the
first frame: `tick` opens it on frame 3 when `open-on-start` is set. Its data
is cached by the index version, the day, the recent list and the Inbox's
counts, so a frame without changes does no queries. Lists draw only the rows
in view. No section has a query of its own: recent comes from the workspace's
list, tasks from the Agenda, the view from the views engine, the Inbox from
the agent inbox, counts from the index.

**Pinning.** There was no pin concept, so `[home] pinned` holds paths and a
command toggles it. Paths that no longer exist are listed as missing rather
than dropped, because a note on another device may not have synced yet.

**A `.base` as the view.** Home runs the saved query of one view of the file
(the same spec the Bases surface runs for boards), read-only. Formulas and
summaries are not computed here; the page says so.

**Writing stats.** "Words today" is the vault's words now minus its words the
first time Home was drawn that day on this device, kept in a device-local file
because a synced baseline would make every device's number wrong. It counts
net change, so deleting text subtracts.

**Keyboard.** Every item is a focusable button; Tab moves, Enter opens, `/`
focuses quick capture.

## Not done

- A "Home" sidebar for mobile widgets (no mobile yet).
- Tidy rules that need the vault (tags in the wrong case across notes, link
  targets). The linter is per note by design; vault-wide checks are the
  Inbox's.
- Several Homes or a note as Home. The page is the same on every device by
  design; a homepage *note* already works by pinning it.

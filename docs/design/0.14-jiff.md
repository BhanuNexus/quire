# Quire 0.14: chrono to jiff, with one date parser and one date formatter

Status: current
Area: dates and times in every crate: parsing, formatting (templates, periodic notes), the local clock, time zones
Code: `crates/quire-base/src/dates/` (the parser, the formatter, the clock), its oracle test `crates/quire-base/tests/chrono_oracle.rs`; every crate that used `chrono`

The owner decided on 2026-11-24 that 0.14 moves from `chrono` (marked unmaintained, RUSTSEC-2026-0543) to `jiff`, with one date parser. This note is the decisions taken before any code (step 0), then a build log.

## Decided (step 0)

1. **Recurrence keeps its own code; `rrule` stays a test oracle.** `rrule` is already only a dev-dependency of `quire-plan`: recurring tasks use Quire's own RFC 5545 subset (`crates/quire-plan/src/recur.rs`), and `rrule` checks it on 10,000 random rules (`matches_rrule_on_random_rules`). Nothing to replace. `chrono` and `chrono-tz` stay in `Cargo.lock` only as dev-dependencies (the `rrule` oracle, and `chrono` as the oracle of the format tests below); no shipped binary links them. `deny.toml` keeps both ignores with that reason. What remains: drop the oracles (and the ignores) once the pinned outputs are trusted, or when `rrule` moves off chrono.
2. **One parser and one formatter, in `quire_base::dates`.** Every place that reads or writes a date calls it:
   - front matter and task fields (`YYYY-MM-DD`, `YYYY-MM-DD HH:MM`, `YYYY-MM-DDTHH:MM`), the agenda and time entries (RFC 3339 with offset), reminders (`YYYY-MM-DD HH:MM`), recurrence `UNTIL` (`YYYYMMDD`);
   - templates (`{{date:…}}`, `{{time:…}}`) and periodic-note names: **strftime patterns typed by people**, formatted and (for periodic notes) parsed back;
   - MCP `parse_time`/`until_any`, CLI flags (`--since`, task dates), import (Obsidian Bases expressions, Joplin, timestamps), sync (HTTP `Date` headers, S3 `x-amz-date`), intel (dates in text, `valid_until`).
3. **User-visible output does not change.** jiff's `strtime` differs from chrono's `format` (`%c`, `%x`, `%Z`, `%q`, `%N`, `%Q`, flags, padding of `%Y` outside 0..9999, `%#z`). So `quire_base::dates` has its own strftime that reproduces chrono 0.4.45 (without locales: English names), driven by jiff values. An oracle test written **first** runs it and chrono over a grid (every specifier with every flag, compound patterns, malformed patterns; dates across year edges and ISO-week edges; times across noon and midnight with fractions; naive, UTC and fixed offsets including seconds) and requires the same text, the same refusals (chrono's `Item::Error`) and the same "cannot format" cases (where chrono's `to_string` panics, as `%#z` did, or a naive value meets `%z`: here an error). The parser is checked the same way for the patterns periodic notes use. Differences found are listed in "Behaviour differences" below with the decision (emulate, or document).
4. **The clock and time zones.** "Now" and "today" come from `jiff::Zoned::now()` in the system zone (`quire_base::dates::now_local`). jiff reads the system tz database on Unix and macOS and uses the bundled one on Windows (`tzdb-bundle-platform`, jiff's default). Local times that fall in a DST gap or fold (a reminder at 02:30 on the night clocks change) are resolved as chrono's `LocalResult` was used at each call site: `single()` callers (a gap or a fold gives nothing) keep that, `earliest()` callers keep the earlier instant; jiff's `Disambiguation::Reject` and `Earlier` express both, and tests pin a gap and a fold in a fixed zone. Licence and advisories: `cargo deny check`. Size: measured on the Linux x86-64 release build against the edition budgets (full 76 MiB, Lite 48 MiB).
5. **Bytes on disk stay identical.** Dates written to files that persist or sync: ledger and proposal archive month folders (`%Y-%m`, UTC), trash stamps (`%Y%m%d-%H%M%S`, local), time entries (`%Y-%m-%dT%H:%M:%S%:z`), captured pages (`captured:` RFC 3339, seconds, `+00:00` style), reminders' fired keys (`%Y-%m-%d %H:%M`), recurrence `UNTIL=%Y%m%d`, imported timestamps (`%Y-%m-%dT%H:%M:%SZ`), front matter dates written by tasks (`%Y-%m-%d`, `%Y-%m-%d %H:%M`). Each goes through the formatter the oracle pins, and a round-trip test reads a value written by 0.13 (the fixture strings are copied from current main's tests and formats).
6. **Migration order and guard.** Bottom-up, one commit per crate: base, vault, plan, index (date call sites only: another builder is in that crate), agent, intel (same), sync, import, mcp, web, app, cli, desktop, sync-server. `chrono` leaves each `Cargo.toml` as it goes, then the workspace dependency. `clippy.toml` gets `disallowed-types` for `chrono::*` so it cannot come back outside the oracle tests.

## Behaviour differences

The oracle (`crates/quire-base/tests/chrono_oracle.rs`) compares 3.7 million formatting cases (every specifier with every flag and malformed patterns, on the 365 days of 2026 and edge dates from year -1 to 9999, eight times of day, naive, UTC and nine fixed offsets including offsets with seconds) and 690,000 parsing cases (date, time, date and time, with offset; what the patterns write, lower-cased, unpadded, with spaces or trailing text). All agree, including the refusals and the "can't write" cases. jiff's own `strtime` is not used for either.

- **Leap seconds.** chrono kept a parsed `:60` second as a leap second; jiff has none, so `23:59:60` reads as `23:59:59.999999999` (in RFC 3339, RFC 2822 and patterns). Nothing in Quire writes a leap second.

# Quire 0.11: task notes, time tracking and boards

Why: task management is the second-busiest plugin cluster in Obsidian
(TaskNotes alone +640k downloads in 30 days, growing about three times
faster than Tasks), and the busiest new Obsidian request this quarter is
a Bases kanban with manual card order, swimlanes and coloured columns
(research refresh, Nov 2026). Quire had task notes (0.9 §E.2) and a
quire-view kanban; this release makes them a task manager, first-party,
plain Markdown, and readable by TaskNotes users.

File formats: [tasks.md](../formats/tasks.md) (task notes, time entries,
the timer) and [boards.md](../formats/boards.md) (order, swimlanes,
colours, maps).

## 1. Task notes (`quire-plan::task_note`)

* A note is a task with `type: task`, or the task tag in its front-matter
  `tags` (`task`, TaskNotes' default). One reader, `task_note::read`,
  serves the agenda, views (`quire-index` now depends on `quire-plan`)
  and the CLI; the two copies of 0.9 are gone. (`Index::tasks`, behind the
  sidebar's Tasks tab and MCP, still lists task lines only: its callers
  tick a task by its line.)
* Properties are read under Quire's and TaskNotes' names (a table in
  `Prop::names`), and written under the name the note already uses, else
  in the vault's style (`[tasks] field_names`). New: `contexts`,
  `projects`, `time_estimate`, `time_entries`, `time_spent`,
  `complete_instances`.
* `[tasks]` in vault.toml: folder, task tag, statuses (board columns),
  done statuses, offered tags, field-name style, pomodoro lengths. Kept
  in the vault so every device agrees on what "done" means.
* Ticking a recurring task note keeps it open and moves its dates to the
  next occurrence (TaskNotes' model), recording the day in
  `complete_instances`; a non-recurring one gets the done status and a
  completion date.
* Convert task ↔ note both ways (`from_inline`, `to_inline`), checked by a
  seeded property test that inline → note → inline gives the same task.
  Converting back trashes the note only when it holds nothing but its
  front matter and title, so no text is lost.

## 2. Time tracking (`quire-plan::{time, timer}`, `quire-app::task_timer`)

* **Entries** are `{start, end}` items in a front-matter list, ISO 8601
  with offset. Front matter's small reader keeps lists of maps as raw text;
  `time::parse_entries` reads them (block items or flow maps, both name
  styles), and `frontmatter::append_list_item` appends one item without
  touching other lines.
* **Inline tasks keep a total**, `[time:: 1h25m]`. *Decision:* a line has
  no room for sessions, and growing it with one field per session would
  bury the task. Converting to a note keeps the total (`time_spent`);
  the weekly report needs sessions, so it counts task notes.
* Sessions under a minute (a timer started by mistake) aren't logged.
* **One timer per device**, `<config>/task-timer.json`, shared by the app
  and `quire-cli tasks start|stop|status|log|report`. *Decision:* the vault
  is written once per session, when it stops, not every minute, so a
  running timer causes no sync churn and no conflicts, and nothing
  half-written is left if Quire is killed (the file still holds the
  start). A timer from another vault is shown as such and must be stopped
  there.
* **Pomodoro**: `Running::advance` moves work → break → work, one phase per
  call; each finished work session is recorded at its scheduled end. A
  break that ended long ago (Quire was closed) starts work again from now,
  so nobody is credited for time they weren't there. Notifications go
  through `notify-rust` (not in tests or with `QUIRE_NO_NOTIFICATIONS`).
* **Where**: Ctrl+Shift+M (start/stop on the caret's task line or the open
  task note), "Start a pomodoro on this task", "Stop the task timer", the
  status bar (⏱ or 🍅 with a clock; click stops), ▶ on agenda rows and
  board cards (right-click: pomodoro), and the CLI.
* **Views**: `from: tasks` gains `time_spent`, `time_estimate`
  (sorted by minutes), `contexts`, `projects`, and the note's own
  `status`; `status = open|done` still works. "Time this week" (and the
  agenda's Time tab, and `quire-cli tasks report`) shows minutes per task
  and day; sessions past midnight count on both days.

## 3. Agenda

A mode switch: **List** (as before, plus task-note cards with status,
priority, due, contexts, projects and spent-versus-estimate), **Board**
(task notes by status, the vault's statuses as columns), **Calendar** (a
month of open tasks by scheduled ⏳ and due 📅) and **Time** (the week).
"+ Task" and Ctrl+Shift+K open "New task…"; quick capture has "New task…" too,
carrying what was typed.

## 4. Boards (`desktop::board_ui`)

One board for quire-view kanban, `.base` kanban and the agenda board.

* **Manual order**: a drop computes its index from the pointer against the
  column's card rectangles; the column's ids, as shown, with the card at
  that index, are written to the view (`order.<column>`) or base
  (`cardOrder`). Notes are never rewritten for order. *Decision:* storing
  order in a note property (as the forum request suggests) rewrites up to
  every card's note per drag and syncs all of them; one line in the view
  changes one file.
* **Swimlanes** by a second property (`swimlanes:` / `swimlaneBy`); a drop
  in another lane sets that property too.
* **Coloured columns** (`color.<column>` / `columnColors`), set by
  right-clicking a heading: a tint and a stripe, readable in light and dark.
* **Editable cards**: status, priority and due as chips with menus. Task
  notes are written under their own property names, task lines get their
  field (or a tick), plain notes their front matter, all through the
  existing write path with history. Columns grouped by `status` follow
  the vault's `[tasks] statuses`; groups by `priority` sort by rank.
* **"+" per column**: a title, then a note from the view's `new:`
  template, a task note (task boards), or a plain note in the view's
  folder, with the column's (and lane's) value set.
* `.base` writes go through `base::set_view_key`, a line-level editor:
  unknown keys, comments and other views keep their bytes (tested with an
  Obsidian-style file).

## 5. Bases views

* `groupBy` (deferred in 0.10) is read as Obsidian writes it (property and
  direction) and groups tables (a heading row per group), cards and boards.
* `type: kanban` and `type: map` are views of their own.
* **Map**: pins from `lat`/`lng` or `location: [lat, lng]` on Natural
  Earth's 1:110m land outline, public domain, 21 KB bundled
  (`quire-app/assets`). The polygons are triangulated once (ear clipping)
  in longitude/latitude; the projection is linear in both, so the mesh is
  only transformed per frame. Pan, zoom about the pointer, fit to pins,
  click a pin to open its note. No network.

## 6. Tests

* `quire-plan`: time-entry property test (5,000 random sessions in random
  offsets: write and read back, day split sums, totals, durations),
  recurring task-note property test (3,000 rules: dates move together to
  `recur::next_occurrence`), inline ↔ note round trip (2,000 lines),
  pomodoro cycles and the restart case, recording to notes and lines.
* `quire-markdown`: appending list items keeps other bytes (CRLF, flow
  lists, comments); inline fields by key.
* `quire-index`: task-note fields and times in views, kanban order round
  trip (parse, run, move, write the block, run), swimlanes, colours,
  quoted column names, map locations.
* `quire-import`: `.base` kanban and `groupBy`; Quire's keys added,
  replaced and removed with Obsidian's unknown keys, comments and other
  views byte-identical; CRLF.
* `quire-app`: a timer survives a restart (a second workspace stops it and
  the entry lands in the note), pomodoro recording, recurring task notes,
  new task notes, the week report, conversion both ways, the bundled
  outline (decoded, and triangles covering the land's area within 1%).
* `quire-cli`: start, status, switch task (logs the first), stop on a task
  line, ambiguous names, `log` and `report` against a real folder.
* `quire-desktop`: the new dialogs in `layout_check`, the map projection,
  colours, the "New task…" form.

## 7. Not in this release

* Time entries on task lines (see 2); a weekly report of inline tasks.
* TaskNotes' `reminders` list, `blockedBy` dependencies and custom property
  names (only TaskNotes' defaults are read).
* Editing a map pin's place on the map; map tiles of any kind.
* Card order on the agenda's own board (it has no view to keep it in; use a
  quire-view board).
* Sync of the running timer between devices (one timer per device, by
  design).

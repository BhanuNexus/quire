# Quire 0.10: the AI workstream

What 0.10 changes in on-device AI, Ask, tool calls, voice notes and the
calibration of the trust features, why, and what is still open. Builds on
docs/design/0.9.md §3.C and §3.D; the formats are in
docs/formats/engine-protocol.md and docs/formats/model-catalog.md.

## 1. Lighter local models

**Problem.** WS-D's spike measured Qwen3 1.7B Q4_K_M at 5.1 GB after a
256-token prompt with candle 0.11's `quantized_qwen3`, against 1.6 GB in
the 0.9 design: candle keeps the 152k × 2048 token table as f32 (1.2 GB),
and on x86 with AVX2 or AVX-512 repacks Q4_K and Q6_K weights into wider
tiles on first use, keeping both copies. Its prompt path also keeps a
second, growing copy of the KV cache.

**Change.** `apps/quire-ai-engine/src/qwen3.rs` is the engine's own copy of
candle's model (MIT or Apache-2.0, attributed in the file), using only
candle's public API:

* the token table stays a `QTensor`/GGUF block vector and only the rows a
  prompt uses are dequantized; Qwen3 ties the output projection to it, so
  one quantized copy serves both;
* weights that stay compact are read straight from the GGUF file into
  candle's block vectors (`GgmlDType::from_data`) and multiplied with
  candle's block kernels (`QuantizedType::matmul_t`), which never repack;
* `Repack` chooses what candle may still repack: `Q8` by default (the Small
  model's `Q8_0`: tiles the size of the blocks, 3–4× faster prompts), `All`
  with Settings → AI → Advanced → "Faster prompts, more memory", or `Never`;
* one KV buffer serves both decoding and prompt chunks; the rotary tables
  cover the context the engine allows (8,192), not the model's 40,960.

**Result** (model-catalog.md has the tables): Balanced uses 1.2 GB loaded,
1.3 GB after a 256-token prompt and 1.65 GB after 1,024 (candle: 2.4, 5.1,
and killed by the OOM killer on the 8 GB VM). Writing speed is the same
within this VM's noise; prompts are read at about 60% of candle's speed
unless "Faster prompts" is on. The catalog's `ram_mb` and `min_ram_gb` and
onboarding's suggestion (Balanced from 8 GB) follow.

An f16 token table (the other option in the brief) was not needed: a
quantized table costs nothing extra and dequantizing a few rows per token is
negligible.

**Windows memory.** Onboarding read memory on Linux and macOS only, so
Windows always got Small. It now asks PowerShell
(`(Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory`), then
`wmic ComputerSystem get TotalPhysicalMemory /value`, with no console window
and no unsafe code, once per run. `sysinfo` was the other option; it would
add a dependency to both editions for one number.

## 2. Tool calls from small models

`quire_ai::toolcall::read_calls` repairs a `<tool_call>` block: code fences,
single quotes, trailing commas, Python literals, bare keys, words after the
object, several objects or an array, `arguments` as a string or spread
beside `name`, OpenAI's `{"function": …}` form, and missing closing brackets
*only when the model closed the block*. The engine's `ReplyParser` also ends
a block at the next `<tool_call>`, drops `<think>` blocks and a stray
`</think>`, ignores everything after a `<tool_response>` the model invents,
and reads a reply that is nothing but a JSON call as a call when it names an
offered tool. Fixtures written from Qwen3's published function-calling
example (`get_current_temperature`, `get_temperature_date`) cover each case,
streamed three characters at a time.

**Safety.** A block that can't be read becomes a call with no name and
`_unparsed`. The agent loop (`quire_assistant::runner`) then runs *no* call
of that turn, records it as a failed step ("asked it to write it again"),
and sends one short correction as a user message; the half-read turn is
kept as text only, so no unanswered `tool_use` goes back to a provider. A
second unreadable turn ends the run ("Nothing was run").

**Cut-off calls (0.10.2, security review #3).** A call cut off by the token
limit could be "repaired" into a call with partial arguments (a shorter
list of lines to delete) and run. Now brackets are added only for a block
the model closed with `</tool_call>`: never for a block ended by the next
`<tool_call>`, never for a reply that is only JSON (it has no closing tag),
and never at the end of a reply. `ReplyParser::finish(ended_turn)` gets the
stop reason; unless the model ended its turn (not the token or context
limit, nor a stop sequence) a call still open, or a bare-JSON call, is a
bad call. And whatever the provider, the runner refuses every call of a
reply whose stop reason is `max_tokens`, with the same one correction.
Tests: `template.rs` (`cut_off_calls_are_never_run`, and fixtures with
`"stop": "max_tokens"`), `runner.rs`
(`a_call_cut_off_at_the_token_limit_is_never_run`).

## 3. Voice notes

* **Recording** (desktop, feature `voice`, on in the full edition): `cpal`
  0.18 (Apache-2.0; ALSA on Linux, so the full edition now links
  `libasound.so.2`, and building it needs `libasound2-dev`). The microphone
  is open only between Record and Stop (or Discard, or closing the dialog,
  which saves what was recorded). Recordings stop at 10 minutes. Quire Lite
  has no `voice` feature: the command, the quick-capture button and the
  Settings controls aren't offered.
* **The file**: 16 kHz mono 16-bit WAV in the vault's attachments folder,
  "Voice note <date> <time>.wav", embedded as `![[…]]`. No pure-Rust Opus
  encoder is mature enough to ship; WAV at 16 kHz is 1.9 MB a minute.
* **The transcript** goes under the embed in a `> [!ai] Transcript of the
  0:42 voice note · <what wrote it>` callout. `[voice] transcribe`:
  * `""` (default): no transcript; nothing leaves the computer.
  * `device`: Whisper tiny/base/small in the engine (`transcribe`, protocol
    2). Offered only while on-device AI is (the experimental switch); the
    Whisper entries are unpinned like the other models.
  * `provider`: the recording is sent to the OpenAI-compatible provider of
    Settings → AI (`POST /v1/audio/transcriptions`, multipart,
    `whisper-1` by default). The dialog says so in amber before Record.
* **Where it goes**: "Record voice note…" inserts at the cursor of the open
  note (or today's note when none is open); the "Voice note…" button of quick capture
  sends it to today's note.
* **Protocol 2.** `transcribe {model, audio_path, language}` →
  `{text, language, seconds}`. Engines accept protocol 1 or 2 in `hello`;
  the app checks the engine said 2 before asking.

Not done: transcribing audio already in a vault (optional in the brief), a
waveform, and streaming the transcript while Whisper works.

## 4. Ask streams

Ask's model mode moved from the 0.8 `LanguageModel` to the `ChatModel`
features use (`Workspace::trust_chat()`), on its own thread: the dialog
shows the answer as it is written ("Writing…"), with Stop, which keeps what
was written and marks it "(Stopped.)". A reply that is turning into
`NOT_FOUND` isn't shown while it streams. Closing the dialog stops it. The
agent panel already streamed (its runs use the same `ChatModel`).

## 5. MCP `ask` when it abstains

`ask` now returns `nearest`: up to three passages, each with its anchor
(path, lines, quote narrowed to the question, `uri`, `citation`, `trust`),
and lists them in the text as "Nearest passages (they don't answer it)";
`citations` is empty then (nothing is cited). The output schema gained
`nearest`; the recorded MCP sessions were re-recorded.

## 6. Calibration

`quire-cli eval` (feature `eval`) gained:

* `--embedder mock` (a loopback `/v1/embeddings` serving deterministic
  hashed vectors: words, word pairs and character 4-grams, 384
  dimensions) and `--embedder endpoint --url … --model …` (any real
  server), so the endpoint embedder path and the neural τ_sem run offline;
* per run: the abstain features (best passage similarity and coverage, for
  answerable and unanswerable questions) and a τ_sem sweep (wrong "Not
  found"s and abstain recall at each τ);
* `sample-vault [dir]`: the repository's sample vault with the 12
  answerable questions `ask`'s test guards and 10 unanswerable ones;
* `contradictions [--judge endpoint …]`: 32 labelled claim pairs (10
  contradictions, 8 tensions, 8 compatible, 6 unrelated) through the app's
  steps (vectors, candidates, judge, Inbox cut-offs) with a scripted judge,
  scored as Inbox precision and recall, with a sweep of the cut-offs.

The numbers and the decisions are in §6.1 below and in 0.9.md §C.4/§C.5.

### 6.1 Results

* **τ_sem (neural): 0.35 → 0.20.** With the mock embedder the sample
  vault's answerable questions reach similarity 0.21–0.39 with coverage as
  low as 0.27, so 0.35 said "Not found" to 2 of 12; 0.20 is the highest
  value with none on either set. The synthetic suite's answerable questions
  all have coverage 1.0 and never abstain. LSA's 0.30 is unchanged.
* **Contradictions: cut-offs unchanged** (0.75 / 0.85). Precision 0.923,
  recall 0.667 with the scripted judge; lower cut-offs would raise recall,
  but the judge is hand-written, so that isn't evidence.
* Tables: docs/agents.md "Measuring retrieval"; notes in 0.9.md §C.4 and
  §C.5.

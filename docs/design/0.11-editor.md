# Quire 0.11: the editor workstream

Status: built on `feat/0.11-editor`. Owner: the 0.11 editor work.

What 0.11 adds to the editor: a formatting toolbar, command
customisation with macros, four small gaps (Mermaid pan and zoom,
drawings in PDF export, links and math in canvas cards, Vim's Ctrl+V),
and typing that stays smooth while the Insights panel and the index are
busy. The market research for 0.11 put "formatting toolbar and command
customisation" at +288k downloads in 30 days across Editing Toolbar,
Commander and Note Toolbar, a gap for Quire.

## 1. Formatting

### 1.1 One edit for every cursor (`quire-markdown::format`)

Every formatting command is a pure function from the buffer and all
selections to one `Transaction` and the selections after it, so a button
press or a shortcut is one undo step, and multiple cursors are formatted
together. `quire-app::format_cmds` maps commands to these functions; the
desktop's fast editor runs them on all its cursors (`FastEditor::format`),
and `Workspace::run` runs them on the note's selection (classic editor,
CLI, tests).

The toggles read the Markdown around each selection:

| Selection | Bold (Ctrl+B) gives |
|---|---|
| `make «this» bold` | `make **this** bold` |
| `make **«this»** bold` or `make «**this**» bold` | `make this bold` |
| a caret in `**th|is**` | `th|is` |
| a caret in a word, `th|is` | `**th|is**` |
| a caret between spaces | `**|**`, and pressing again takes the pair out |
| `«this »` | `**this** ` (spaces stay outside the markers) |
| part of a bold span | the whole span is unbolded |
| `- «one`↵`- two»` | each line's text is wrapped on its own, after its list marker |

* Bold and italic read runs of `*` and `_`: a run of two or more holds
  bold, an odd run holds italic, so `***x***` unbolds to `*x*` and
  un-italicises to `**x**`. A bullet's `* ` and `snake_case` underscores
  aren't emphasis.
* Inline code and math over several lines become a fenced block
  (```` ``` ```` or `$$`); the same command inside one takes the fences
  away.
* Line commands (headings 1–6 and paragraph, bulleted and numbered lists,
  tasks, quote) work on every line any cursor touches; blank lines in a
  multi-line selection stay blank. All lines at the level already: back to
  plain lines.
* Links: `[selection]()` with the caret in the parentheses, `[](url)` for
  a selected URL, and the link back to its text when the selection is in
  one. Wikilinks (`Ctrl+\`) the same with `[[ ]]`.
* Blocks go on lines of their own: a table (with "Column 1" selected; in a
  table the button tidies it instead), a horizontal rule (with a blank
  line above, so the line before doesn't become a heading), a callout
  (`> [!note]` around the selected lines, or the callout taken apart), a
  math block, a code block.
* A footnote: `[^n]` after each selection with the next free number, and
  `[^n]: ` at the end of the note; with one caret, the caret moves to the
  definition.
* Insert image or attachment: a file dialog; the files are copied into the
  vault like dropped files and linked at the caret.

Text is only ever wrapped and unwrapped: no toggle deletes anything but
the markers it added. Every edit is undone with one Ctrl+Z.

### 1.2 The toolbar (`toolbar_ui.rs`)

Off by default: View: Formatting toolbar, or Settings → Toolbar.

* Above the editor, wrapping to more rows in a narrow window. The default
  buttons: bold, italic, strikethrough, highlight, code | link, wikilink |
  heading menu (H1–H6, Paragraph), bulleted and numbered list, task,
  quote, callout | table, math, footnote, rule, attachment.
* **Customisable** (Settings → Toolbar): add any command or macro, a
  separator or the heading menu; remove; move up and down; an icon (an
  emoji or a few letters; empty: the command's own icon, else the first
  letters of its title) and a label (the tooltip). Stored in
  `[toolbar] items` (missing: the defaults, empty: no buttons).
* **Floating toolbar** (`[toolbar] floating`): bold, italic,
  strikethrough, highlight, code, math, link and wikilink in a small bar
  above the selection's start, while text is selected in the fast editor
  and not while dragging a selection. It flips below the selection near
  the window's top and stays inside the window.
* **Keyboard:** F10 ("Move focus to the formatting toolbar") gives the
  first button focus, even while the toolbar is off (it shows until you
  leave it); ← → Home End move, Enter or Space press, Escape goes back to
  the note. Focus is drawn as an accent ring.
* **Tooltips** name the command and its shortcut as Settings → Commands
  has it ("Bold (Ctrl+B)", "Bold (⌘B)" on macOS).
* **Vim:** the buttons and the shortcuts work in every mode. In Insert
  mode they are part of the insert session, so one `u` in Normal mode
  undoes the session including them, as Vim would.

## 2. Command customisation (`quire-app::keymap`, `commands_ui.rs`)

Settings → Commands lists every command with its category and shortcuts,
filtered by a search box.

* **Change** records the next key press (Escape cancels; the Settings
  dialog doesn't close while recording, and Ctrl+C/V/X arrive as keys);
  **+** adds another shortcut; **✕** removes them; **Reset** brings back
  Quire's. **Reset all shortcuts** at the top.
* **Conflicts** are checked for Windows, macOS and Linux at once, because
  settings are copied between computers:
  * another command or macro has the keys (blocking: "Use it here and
    remove it there", "Use it anyway", or Cancel);
  * keys the system or every text field keeps (blocking): Ctrl+C/V/X
    everywhere, Alt+Tab, Alt+F4 (Windows, Linux), Ctrl+Esc and
    Ctrl+Alt+Del (Windows), ⌘Q, ⌘H, ⌘M, ⌘Space, ⌘Tab, ⌘\`, ⌘⌥Esc and
    ⌘⇧3/4/5 (macOS), Ctrl+Alt+T, Ctrl+Alt+Delete and Ctrl+Alt+arrows
    (common Linux desktops);
  * **AltGr** (a warning): Ctrl+Alt is AltGr on Windows, so on layouts
    where AltGr with that key types a character, typing wins (the app
    drops a Ctrl+Alt shortcut in a frame that typed text, as since 0.9);
  * **Option** (a warning): ⌥ with a letter, digit or sign types a
    character on macOS; the shortcut runs and the character is dropped.

  Two commands left with the same keys are listed in red at the top: the
  first one runs.
* Ctrl means ⌘ on macOS, so one setting works on every platform. The
  Control key on macOS (⌃) can't be recorded.
* **Pin** (📌) puts a command or macro at the top of the command palette
  when nothing is typed, in pin order, marked with a pin; while typing,
  pinned entries rank a little higher.
* **Macros:** a name and a list of commands (picked from the same list,
  moved up and down), no scripting, as in Commander. A macro can have
  shortcuts, be pinned, be a toolbar button and is in the palette as
  "Macro: name". Its commands run one after another, each its own undo
  step; it stops at a command that opens a dialog (the rest would run
  behind it), stops when a command needs a note and none is open, and
  skips commands this version doesn't have. Renaming a macro keeps its
  shortcuts, pin and buttons.
* The palette and the shortcut sheet (Ctrl+/) show the shortcuts in
  effect.

Storage: device-local `settings.toml`, its own tables, and keys this
version doesn't know are kept (a newer Quire's commands, macro fields and
button fields survive a save):

```toml
[commands]
pinned = ["DailyNote", "macro:Tidy"]
[commands.keys]
Bold = ["Ctrl+Shift+B"]          # replaces the defaults; [] unbinds
"macro:Tidy" = ["Alt+F9"]
[[commands.macros]]
name = "Tidy"
steps = ["FormatTable", "Save"]

[toolbar]
show = true
floating = false
[[toolbar.items]]
command = "Bold"
icon = "B"
label = "Bold"
```

Commands are named by the variant name (`Command::id`, `"Bold"`), which
the table macro now records with `stringify!`, so names can't drift.
A shortcut that doesn't parse, or a command this version lacks, is
skipped, never an error. New 0.11 commands have no default keys except
F10, so they can't take keys from the other 0.11 work.

## 3. Small gaps

### 3.1 Mermaid diagrams (`diagram_ui.rs`)

In notes and in the preview: drag to pan, Ctrl+wheel (or a pinch) to
zoom around the pointer (0.25× to 8×), double-click to reset. The plain
wheel still scrolls the note. Buttons on the diagram's corner while the
pointer is over it (or while it is moved): zoom out, zoom in, 1:1, full
screen and, in the editor, "Edit the diagram's source" (a click on a
diagram used to open the source; now a drag pans, so that is a button).
Full screen fits the window, and there the plain wheel zooms. Escape
closes it. Formulas keep their click-to-edit.

### 3.2 Drawings in PDF export

`![[Plan.excalidraw]]` (the file, or the drawing note
`Plan.excalidraw.md`) is the drawing's SVG in the typeset PDF, as in HTML
export, Copy as HTML and published sites (which had it since 0.10). The
pictures a drawing embeds pass the same vault path checks. Typst draws
the SVG with its embedded fonts, so the drawing's text is real text in
the PDF.

### 3.3 Canvas cards

* **Links in cards are clickable:** a wikilink opens the note (and
  heading), a web link opens the browser. The pointer becomes a hand and a
  tooltip says where it goes. Shift or Ctrl and a click still select the
  card; a double-click still edits it. How: a card is drawn once with the
  preview's renderer and kept as shapes; each link is a text shape in the
  link colour, in reading order, so the n-th one is the n-th
  `[text](url)` of the card's Markdown (a link whose text matches a later
  one skips ahead).
* **Math in cards:** `$x^2$` and `$$…$$` are typeset as in the preview. A
  card whose math is still being typeset isn't kept until it is done.

### 3.4 Vim's Ctrl+V

Why it didn't work: egui-winit turns Ctrl+V (⌘V) into
`Event::Paste(clipboard)` and drops the key, and with an empty clipboard
it sends nothing at all. The Vim adapter treated a paste in Normal mode
as Ctrl+V, so with something on the clipboard block mode worked and with
nothing it didn't.

The fix: the app turns egui-winit's clipboard shortcuts off
(`NativeOptions::clipboard_shortcuts = false`) and handles the keys itself
in `raw_input_hook` (`app::clipboard_keys`), with egui-winit's own rules
(⌘ or Ctrl alone with C, X, V; Shift+Delete, Ctrl+Insert, Shift+Insert on
Windows; the Copy, Cut and Paste keys). Copy and cut become clipboard
events as before; paste asks the window for the clipboard
(`ViewportCommand::RequestPaste`, read by egui-winit's own clipboard, so
Wayland and images work as before). In Vim's Normal and Visual mode with
the note focused, Ctrl+V stays a key and reaches Vim, whatever is on the
clipboard. In Insert mode it pastes. A paste in Normal mode from
elsewhere puts the text before the cursor.

Ctrl+Q, Vim's other key for Visual block, closed the window. Quire binds
nothing to it, but egui does: `Options::quit_shortcuts` defaults to
Cmd+Q (Ctrl+Q on Windows and Linux), checked in `Context::end_pass`,
after the app's frame, so Vim saw the key and then the window closed.
`raw_input_hook` now empties `quit_shortcuts` while Vim has the keys
(Normal or Visual mode, the note focused) on Windows and Linux, and puts
Ctrl+Q back otherwise. ⌘Q on macOS is a different key from Ctrl+Q and
always quits.

egui 0.37 also sends modifier keys as `Key` events (`ControlLeft`…);
recording a shortcut waits for the key that goes with them.

## 4. Typing smoothness

### 4.1 The Insights panel

The panel laid out every heading of the outline and every outgoing link
each frame, cloned the outline and resolved each link against the index
each frame: for the 100 KB test note (about 1,000 rows) about half a
keystroke's UI time (0.10-perf §4). Now (`panels::InsightsRows`):

* the outline and links follow the note once typing pauses (300 ms), or
  at once for another note; until then the last ones stay;
* only the rows in view are laid out and drawn; the outline's rows have
  one height, and the links' wrapped positions are worked out once per
  panel width and list.

### 4.2 Background threads

The index worker, the parser threads of the first index, the meaning
(semantic) worker, the job runner, the PDF-text reader and the big-note
Insights thread run at the lowest normal priority:
`thread-priority`'s safe `set_current_thread_priority(Min)` (nice 19 for
the thread on Linux, the lowest `SCHED_OTHER` priority through
`pthread_setschedparam` on macOS, `THREAD_PRIORITY_LOWEST` on Windows).
No `unsafe` in Quire; the crate is MIT, its dependencies were already in
the tree, and `cargo deny` passes. It needs no privileges, and on an idle
machine the threads run as fast as before.

### 4.3 The editor's headings

The fold arrows asked for the note's headings every frame, cloning the
outline (every heading's text) and converting each offset to a line.
They are now kept per revision (`DocView::headings`), and the outline is
read without a copy.

### 4.4 Measured

The typing run of the CI perf job (`QUIRE_BENCH=typing`, `--profile perf`
with `--features bench`, a 100 KB note in a 10,000-note vault, jobs on),
on the 2-core VM under Xvfb. The machine was shared with two other builds,
so the runs alternated: 0.10.2 (the branch's base), this branch, 0.10.2
again, three typing runs each, medians of the runs:

| Keystroke to frame | 0.10.2 | 0.11 editor | Change |
|---|---:|---:|---:|
| p50 | 5.71 ms | 4.68 ms | −18 % |
| p95 | 9.04 ms | 6.79 ms | −25 % |
| p99 | 12.9 ms | 9.79 ms | −24 % |
| p50 while the 10,000 notes are first indexed | 5.81 ms | 4.46 ms | −23 % |

0.10.2's six runs: p50 5.52–5.94, p95 8.2–9.5, p99 11.0–15.4,
indexing 5.6–6.2 ms. This branch's three: p50 4.62–4.84, p95 6.0–7.8,
p99 9.5–10.4, indexing 4.43–4.66 ms. Under heavier load from the other
builds (load average 3–5) 0.10.2's p95 was 19–21 ms and p99 28–32 ms.

The bench note has 104 headings and 208 links, so the Insights panel was
less of a keystroke than 0.10-perf §4 estimated for 1,000 rows; the
three changes together (Insights rows, the editor's headings, thread
priority) make the difference above. What a keystroke still costs on a
100 KB note is mostly one Markdown parse per revision (the word count
and the fold arrows read it) and laying out the lines in view.

The whole perf job on this branch (`packaging/perf-check.py`, five runs),
every budget met:

| Measure | Budget | Fails above | Median |
|---|---:|---:|---:|
| Index build, 2,000 notes | 420 ms | 525 ms | 356 ms |
| Search, 2,000 notes (p50) | 10 ms | 12.5 ms | 1.07 ms |
| Section search, 2,000 notes (p50) | 15 ms | 18.8 ms | 5.77 ms |
| MCP `view` / `search`, 10k notes | 10 / 50 ms | 12.5 / 62.5 ms | 0.56 / 18.8 ms |
| PDF text per page (p50) | 50 ms | 62.5 ms | 0.27 ms |
| MCP first answer, 200 new PDFs | 500 ms | 625 ms | 1.7 ms |
| Startup: what 10k notes add | 20 ms | 25 ms | 12.4 ms |
| Keystroke to frame, 100 KB note (p95 / p99) | 10 / 16 ms | 12.5 / 20 ms | 7.21 / 11.6 ms |
| Canvas, 1,000 cards (p50) | 8 ms | 10 ms | 2.08 ms |

The typing p95 budget is now 10 ms (was 12): the branch measures
6.8–7.2 ms, so with the job's 25 % margin for noisy runners it fails above
12.5 ms. The p99 budget stays at 16 ms: one run under load reached
22.8 ms.

### 4.5 Known limits

* A process a lowered thread starts inherits its priority on Linux (the
  on-device AI engine, when a background job is the first to need it,
  runs at nice 19 instead of 10).
* A zoomed diagram is the same picture scaled up, so it gets soft past
  about 2×; the full-screen view draws it at the window's size first.

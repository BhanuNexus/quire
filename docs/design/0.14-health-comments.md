# 0.14 codebase health: comment labels

Part of wave 2 of the 0.14 codebase-health pass (plan items "stale workstream
labels" and "design § references"). Comments only: no code changed.

## What was wrong

The 0.9 plan split the work into workstreams `WS-A` to `WS-G` and a foundation
step `F0`. Comments in `crates/` and `apps/` kept those labels (`Owned by
WS-E`, `// ---- WS-C`) and cited the plan by letter (`design §C.4`). A label
means nothing to a reader today, and an agent copies the style into new files.

## What changed

Measured with `git grep -P` over `crates/*.rs` and `apps/*.rs`, before (616bfb7)
and after:

| Pattern | Lines before | Lines after |
|---|---|---|
| `WS-[A-G]` | 190 (87 files) | 0 |
| `\bF0\b` | 11 (8 files) | 1: the file name `docs/design/F0-notes.md` |
| `[Dd]esign (0\.9 )?§` | 258 (195 files) | 2: a usage string and an SQL line, which are not comments |
| `§[0-9A-G]` (any form) | 307 (216 files) | 227: every one now names its note by path, or is an RFC section |

- A workstream or phase label is gone. Section headers in `registry.rs`,
  `commands.rs`, `features.rs` and `tools/mod.rs` now name the feature area
  (`Agent`, `MCP`, `Trust`, `AI`, `Planning`, `Editor`, `Spatial`). "Owned by
  WS-x" sentences are deleted. "Frozen after F0" sentences are deleted.
- `design §X` became `` `docs/design/0.9.md` §X `` in module headers and where a
  comment depends on the section, and was dropped from an inline comment that
  stands alone. Every `docs/design/…md` § reference in `crates/` and
  `apps/` (239) was checked against the headings of the note it names.
- Two `#[expect(dead_code, reason = "… since WS-G …")]` strings in
  `apps/quire-desktop/src/surfaces.rs` lost the label. They are attribute text,
  not code that runs; nothing else outside comments changed.

## The check

`packaging/check-comment-labels.sh` fails the `packaging` job on a `//`, `///`
or `//!` line with a `WS-A`..`WS-G` label, `F0`, `design §`, or a `§` section
with no `docs/design/` path on the line (RFC sections are allowed).
`packaging/test-check-comment-labels.sh` is its self-test. `AGENTS.md` has one
rule line.

## What was left, and why

- `docs/design/0.9.md` still has its workstream section (6.2). It is the plan
  and is marked as one; code no longer points into it.
- The check does not verify that a cited section exists; that was checked once
  by hand-run script for this change.
- The usage string `design §9 measures` in `quire-cli bench` and the SQL
  comment in `quire-sync-server/src/store.rs` are text that runs, so they were
  not touched.

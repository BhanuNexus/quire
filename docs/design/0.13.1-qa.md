# 0.13.1 quality pass

What the quality team of the 0.13.1 hardening pass found and did. Rules for
the pass: behaviour and saved formats don't change, no new features, a
non-test change needs a test that shows the bug. Everything below is
verified by the commands named; what could not be verified says so.

## 1. Flaky and time-dependent tests

Each was read for its root cause first; the fix removes the cause, not the
symptom (no longer sleeps, no retries around an assertion).

| Test | Root cause | Fix |
|---|---|---|
| `serve_cli` (both tests) | The port was found by binding and closing a socket, then handed to the server: another process could take it in between. | The server binds port 0 and prints its port; the test retries the whole start if the bind fails, and waits for the index with a 2-minute deadline instead of a fixed pause. |
| `sync_cli` takeover test | Fixed sleeps between two child processes. | Reader threads collect what each prints; the test waits for the line it needs (`Synced: received 0, sent 1`). |
| `quire-agent` `watch.rs` `notices_a_new_proposal_file` | macOS FSEvents can deliver the events of the folders `start` made late, after the file was written. | `settle()` waits until the watcher is quiet before the test writes; the write retries until seen, with a deadline. |
| `quire-app` secure_state history `.tmp` race | The history writer is a thread; locking a folder converted files while it still had a `.tmp` for a note in it. | The test flushes history before locking (`lock_and_wait`); unlocked-notes test takes one `now`. |
| `task_timer` week report | `week_report` floors minutes **per day**, and the test compared with a total computed from a different clock reading. | The assertion follows the entry the timer wrote. New test `weekly_report_at_the_week_boundary` pins the flooring and the week edge. |
| Unidentified timing-dependent sync suite | `quire-sync/tests/remote.rs` took fixed, pid-derived ports. | `reserve()` takes ephemeral ports. |
| `task_ui` "tomorrow" | Read the clock twice around midnight. | The expected date is bracketed by a clock reading before and after. |
| `drawing_edit` tests | Slept past the 0.6 s autosave delay. | Set `last_edit` into the past or future instead. |

Workspace hunt for `sleep(`, wall-clock in assertions, fixed ports, shared
temp paths, and TZ, locale, HOME or order dependence. About 40 test sleeps
remain; each was read and falls in one of three kinds that cannot make a test
fail by being too short: (a) the pause between polls inside a loop with a
deadline (`vault_sync`, `git`, `jobs`, `sync_cli`, `serve_cli`); (b) a window
in which something must **not** happen (`jobs`: "nothing runs while typing", at
most a weak check, never a false failure); (c) 1.1 s waits for the sync
server's one-second clock to move on before compacting
(`quire-sync-server/tests/harden.rs`). No fixed port remains in a test (the
sync-server and CLI tests bind port 0). The CLI integration tests give each
child its own `HOME` and config folder. The `task_timer` tests' 20 ms pauses
only let a file's modification time differ. Not audited line by line: the
many unit tests that read the local clock for "now" (they compare against a
value taken in the same test and now pass at the day boundary and in both
extreme time zones, shown by the runs below), and locale (Quire formats with
fixed patterns, no `LANG`-dependent call was found).

**Repeat runs** (test binaries run directly, 20 runs per suite and time zone):

| Suite | UTC | Pacific/Kiritimati (+14) | America/Los_Angeles |
|---|---|---|---|
| quire-agent `watch` | 20/20 | 20/20 | 20/20 |
| quire-app `secure_state` | 20/20 | 20/20 | 20/20 |
| quire-app `task_timer` | 20/20 | 20/20 | 20/20 |
| quire-plan `time` | 20/20 | 20/20 | 20/20 |
| quire-sync `remote` | 20/20 | 20/20 | 20/20 |
| quire-desktop `drawing_edit` + `task_ui` | 20/20 | 20/20 | 20/20 |
| quire-cli `serve_cli` | 7/7 | 7/7 | 7/7 |
| quire-cli `sync_cli` | 7/7 | 7/7 | 7/7 |

The CLI integration suites take up to 25 s a run on the shared machine, so
they ran 7 times per time zone (21 each). There is no "before" failure rate:
these races depend on machine load, and each cause above was found by
reading the code and shown by reasoning (and, for the week report, by a
unit test at the boundary), not by catching a failure.

## 2. Loose ends

| Item | Result |
|---|---|
| Inline-timer caret | Not a bug. After starting a timer the caret stays on the task's line; the test asserted line 1 but `caret_line_col` is 1-based and the task is on line 2. The assertion now says 2. |
| Lite-edition tests | `cargo test -p quire-desktop -p quire-cli -p quire-app --no-default-features --locked`: see the status table below. |
| Full-edition `quire-cli` integration tests | Pass (15 unit, 2 + 2 + 1 + 2 + 2 + 2 + 4 integration). |
| Locked folder locking inside the drawing's 0.6 s autosave window | Fixed. Locking now waits (up to `DRAWING_SAVE_WAIT`) until each drawing in the folder has written its pending edits, by asking the open drawing to save at once; a drawing that cannot write ends the wait with the lock refused and a notice (the folder stays unlocked), not with lost text. A drawing with edits that is in "changed elsewhere" counts as unsaved too (review D-L1): the lock is refused until the person chooses what to keep, the same outcome as a note that cannot be saved and cannot keep its encrypted copy. Idle locking asks a waiting folder's drawings once, warns once and tries again after a minute (D-L2). Test: `drawing_edit::tests` lock window, `locking_waits_for_a_drawing_with_unwritten_edits`. |
| Drawing close-time writes keep no history, and nudge sync | Fixed. A drawing closed with edits writes once, keeps a history version and nudges sync (a close-time write is a real change; `save_drawing` calls `sync_nudge`). A change elsewhere found at close is announced as "kept in a copy", not as a question. `Surface::close`; test `closing_a_drawing_keeps_a_history_version`. |
| Settings → Sync create/join/list blocking the UI thread | Fixed. The three calls run on a worker thread, results polled each frame (`sync_*_in_background`, `poll_setup`). The sync storage still decides how long they take; the window no longer freezes. Passphrases and keys are zeroized as before. |
| Undo of an import leaves empty folders | Fixed. `remove_emptied_folders` removes the folders the import created that are empty after the undo, and only those. Test `undo_removes_the_folders_it_emptied`. |
| Board card order lost on rename | Documented, not changed. A card's id is its path, so a rename drops its hand-placed position (it follows the sort order until dropped again); fixing it means a new id scheme in the board state file, which is a persisted-format change. Already stated in [formats/boards.md](../formats/boards.md). |

## 3. GitHub issues

### #3 importer fixtures against the public format docs

`quire-import/tests/documented_variants.rs` adds one test per source for the
variants the format's public documentation (or the app's own help and the
open-source tools that read it) describes: Evernote (DTD attributes, wrapped
base64, `<en-media>`, `<en-todo>`), Google Keep Takeout, Day One JSON, Roam
JSON, Joplin raw, Bear TextBundle, Notion Markdown and CSV, Logseq, HTML
folders, Obsidian Kanban and Bases. Every one passes against the importers
unchanged, apart from two expectations of the test that were wrong (see the
Day One note below). **What is still only hand-built:** none of these was
checked against a real export from the app itself. docs.evernote.com,
help.dayoneapp.com, the Notion and Keep help pages and the GitHub API were
not reachable from the build machine, so every fixture was written from the
documented structure; real exports may carry fields the docs don't mention.
`crates/quire-import/tests/fixtures` (Day One, Joplin, Keep, Roam) hold the
older hand-built samples. Real-export checks are open.

- Day One escapes `\-`; the importer leaves it, because at a line start it
  would become a list. That is intended (it changes no text), and the test now
  says so.
- The Obsidian Kanban doc comment named only `kanban-plugin: board`; the
  plugin writes `basic` in older versions, and the code reads both.

### #4 AI providers: request and response shapes

`quire-intel/src/llm.rs` was compared with the published Anthropic Messages
API (events `message_start`, `content_block_*`, `message_delta`, `ping`,
`error`; stop reasons) and the OpenAI-compatible `/v1/chat/completions`
(Ollama, LM Studio, vLLM and others) from the SDK types and docs that were
reachable. Changes, each with a mock-server test in `tests/providers.rs`:

- An `error` event inside a stream (Anthropic's `overloaded_error`, a
  server's `{"error": …}`) is reported as the provider's error, not as a
  truncated answer. (`err_in_stream`)
- Stop reasons `refusal` (an error that says so), `model_context_window_exceeded`
  (length), `pause_turn` and `end_turn` are handled.
- A 400 that names `temperature`, or `max_completion_tokens` for `max_tokens`,
  is retried once with that changed (`adapt_body`). **Judgement call:** this is
  new behaviour on an error path; it was added because the documented newer
  models reject those parameters and Quire would otherwise fail every request.
  It never retries on any other error, and at most three times. It can be
  dropped with the two helpers and their tests if you would rather not ship it
  in a patch release.

**Live verification is still open.** No request was sent to Anthropic, OpenAI
or a local server: the build machine has no keys and no route. The mock
tests prove that Quire handles the shapes the documents describe, not that
the providers still send them.

### #5 AccessKit in the fast editor

Done within the issue's limits (no new dependency, no unsafe): `view/a11y.rs`
builds, when a screen reader is attached (egui reports it by
`accesskit_update`), a `TextRun` per visible line (long lines are cut into
runs of at most 255 characters, which AccessKit's `u8` word starts need) under the
editor's node, and a `TextSelection` whose anchor and focus point into those
runs; positions outside the visible window clamp to its ends, folded lines to
the next visible one. Without a screen reader nothing is built. Tests build a
real egui frame and read the tree. Not verified: with an actual screen reader
(Orca, NVDA, VoiceOver): none is available here, so how it reads is untested;
that the lines and the selection reach the platform adapter is.
Not exposed: lines outside the window, the text of folded sections, the
caret blink, per-character bounds for wrapped lines (runs carry the line's
rectangle).

## 4. Docs truth pass

README, SECURITY.md, CHANGELOG `[0.13.0]`, `docs/*.md` and `docs/formats/*.md`
were read against the code. Fixed: README size figures and the
`quire-import` layout line; the README now lists drawings in locked folders
and the screen-reader support; the usage text of `quire-cli import` no longer
lists Obsidian as a separate source (an Obsidian vault is a Markdown folder);
one dead anchor in `docs/agents.md`. SECURITY.md matches the code (`--allow-write`
is read-only by default, keys in the keychain with a 0600 fallback).

- Every `quire-cli <command>` in the Markdown files (the design notes and the
  changelog aside) names a command listed by `quire-cli --help`, and every
  `--flag` shown next to it is in that command's help. The only names that
  do not appear are `quire-cli eval …` (a feature, `--features eval`, as
  `docs/agents.md` says) and prose such as "the quire-cli command".
- Relative links and `#anchors` were checked across 140 Markdown files with a
  script that reads `git ls-files`. Three of the four reports were false
  positives of the script (anchors it builds from headings with code spans);
  the fourth was the agents.md anchor.

## 5. Dead code and warnings

- `TODO`, `FIXME`, `XXX` in code: none (the hits are test data, a `XXXX-XXXX`
  key format and a Markdown task in a find test).
- `#[allow]`: every one has a `reason`. Each was turned into `#[expect]` and
  the workspace linted: five were unneeded and are removed (`too_many_arguments`
  on the two board functions, and on three sync functions). The rest are needed.
- `#[ignore]`: four tests, all kept with their reason: the section-search
  benchmark (`quire-index`), the graph timing run (`quire-index/tests`), the
  MCP benchmark (`quire-mcp/tests/bench.rs`, release only), and `print_vectors`
  (`quire-vault`, prints test vectors after a deliberate format change). They are
  tools, not skipped tests. Run in debug: the section-search benchmark
(p50 141 ms, which is a debug figure; the ≤ 15 ms target is for release, not
checked here), the 10,000-note graph rebuild (758 ms) and `print_vectors` pass.
The MCP benchmark needs a release build and was not run.
- Unused public items: a scan for `pub` items of the library crates that no
  other file mentions found 17 (below). They are **not removed**: removing
  public items is a change of no user's behaviour but of several crates'
  API, and one is named in `docs/design/0.10-agentsync.md`. They are listed for
  the owners to decide:
  `quire-agent` `ALL_CHECKS`, `Store::log_here`; `quire-app` `PROVIDERS`,
  `forget_folder_key`, `drift_words`, `Workspace::new_from_template`;
  `quire-assistant` `INGEST_PROMPT_VERSION`; `quire-import` `existing_files`;
  `quire-intel` `without_tools`, `of_note`; `quire-mcp` `REFUSED_METHODS`,
  `with_vault`, `state_dir_for`; `quire-pdf` `plain_pages`; `quire-spell`
  `clear_cache`; `quire-text` `len_delta`, `map_all`.
- Clippy on new code (a11y, drawing close, sync dialogs, tests) is clean with
  the CI's flags in both editions.

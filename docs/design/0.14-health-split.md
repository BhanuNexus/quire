# 0.14 health: splitting the two hottest files

Status: current
Area: `quire-app` sync glue and `quire-mcp` tools: file layout only
Code: `crates/quire-app/src/vault_sync/`, `crates/quire-mcp/src/tools/read/`, `crates/quire-mcp/src/tools/write/`

Items 17 and 18 of the codebase-health plan. Pure moves: no behaviour change,
no renamed public item, no clean-up. The point is that an agent can read one
part of sync, or one MCP tool, in one call, and that the 0.14 sync-performance
and MCP work starts on small files.

## `vault_sync.rs` became `vault_sync/`

`mod.rs` keeps the module doc, the imports and the `mod` / `pub use` lines.
Every child does `use super::*;` and `mod.rs` re-exports each child with
`pub use child::*;`, so `quire_app::vault_sync::X` resolves as before and
nothing outside the folder changed. Items that were private and are now used
across files are `pub(super)` (as are the fields and methods the compiler
asked for).

## `tools/read.rs` and `tools/write.rs` became folders

One file per tool. Each holds `pub(super) fn register() -> Box<dyn Tool>`
(the `tool(...)` call: name, title, description, both schemas) and the tool's
handler and private helpers. `mod.rs` lists the `register()` calls in the
old order, so `ToolRegistry::standard()` and the order test are unchanged.
Helpers that several tools use sit in `shared.rs` (`own_pending` is still
re-exported as `read::own_pending`, `edit` as `write::edit`). The module of
the `outline` tool is `outline_tool.rs` because `outline` is an imported name
in `read/mod.rs`. The one path edit: `revert.rs` writes
`super::super::common::parse_time`.

## Left alone

- `tests.rs` is still one 1,495-line file. Split it by part (store, session,
  setup, worker) when next touched.
- The children use `use super::*;` rather than their own `use` lists, so the
  imports live in each `mod.rs`. Tightening them is a clean-up for later.
- `links.rs` and `canvas.rs` have the same spec-and-handler shape but are
  under 410 lines; not split.

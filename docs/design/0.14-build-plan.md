# Quire 0.14: build plan, wave 0

Status: current
Area: architecture
Code: `crates/quire-base/src/` (new `cache.rs`), `crates/quire-vault/src/` (new `changes.rs`), `crates/quire-markdown/src/{scan,srs,render,callout,cite,format}.rs`, `crates/quire-markdown/src/linter/analysis.rs`, `crates/quire-index/src/semantic.rs`, `crates/quire-mcp/src/server.rs`, `crates/quire-mcp/tests/`, `crates/quire-agent/src/`

The first steps of the 0.14 build, from `0.14-architecture.md` §9. Nothing here is built
yet. Wave 0 is everything that needs no other 0.14 step: the two shared building blocks,
and four small pieces the designs marked "any time". Later waves get their own brief when
this one has merged.

## Rules for every step

- One step, one branch, one worktree with its own `target/`. Merge in the order of the
  table when two steps touch one crate.
- Build and test one crate at a time: `cargo test -p <crate> --locked` and
  `cargo clippy -p <crate> --all-targets --locked -- -D warnings`, with
  `CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0`. Never
  `cargo test --workspace` on this machine (it compiles candle).
- Check `df -h /` before starting; stop below 2 GB free and remove your own `target/`.
- Persisted writes go through `quire_base::fs::write_atomic`. A changed or new on-disk
  format gets a page in `docs/formats/`. A user-visible change gets one changelog bullet.
- A step is done when its tests in the table exist and pass, and the budget column holds.

## What runs in parallel

Two builders at a time, each in its own worktree, about 2–3 GB of `target/` each for these
crates. Never two steps of one crate at once.

| Slot 1 | Slot 2 | Why this pair |
|---|---|---|
| A1 (`quire-base`) | I0a (`quire-markdown`) | disjoint crates; A1 is small and unblocks A2 |
| A2 (`quire-vault`) | I0b (`quire-markdown`, after I0a) | A2 needs A1 merged; I0b rebases on I0a |
| X1 (`quire-index`) | T0 (`quire-mcp` tests) | `quire-mcp` builds on `quire-index`: start T0's build after X1's first compile to share nothing and fight less for CPU |
| X2 (`quire-mcp`, after T0) | sync-speed S1a or local-AI step 1 | X2 is hours; the other slot starts wave 1 |

Order of merges: A1, I0a, A2, I0b, X1, T0, X2. A1 and A2 are the only steps other waves
wait for; if anything slips, protect those two.

# Quire 0.13: typed links polish

Status: built on `feat/0.13-links`. Builds on [0.12-links.md](0.12-links.md);
format in [docs/formats/links.md](../formats/links.md).

0.12 deferred four things: editing `[links]` in Settings, typed links in the
web app and in published sites, and Breadcrumbs' other edge builders. This
note covers what was done for each and what is still not done.

## 1. Settings → Links

**Where it is stored.** `[links]` of `.quire/shared/vault.toml`, through
`VaultPrefs::set_section` like every other settings page. `LinkConfig`
gained `types` (`[links.types.<name>]`, a `color`), `dendron`
(`[links.dendron]`) and `other`, a flattened `toml::Table` that keeps every
key this version doesn't know, in `[links]` and in each type's table.

**Byte identity.** `set_section` (in `quire-vault`'s `prefs.rs`, shared by
every settings page) merges the new section into the existing `toml_edit`
document value by value: a value that already means the same is left alone,
so its comments (also inside arrays), spacing, quoting and inline tables
survive; tables, standard or inline, are merged key by key; a replaced value
keeps its own comments and spacing. A file with CRLF line ends is written
back with CRLF. `prefs.rs` has a test that saves every section unchanged and
compares the bytes, and `relations.rs` has one for `[links]` with comments in
arrays, inline tables and CRLF. One more rule, in `LinkConfig::store`: a
key that is at its default and isn't in the file is not written. Without it,
saving once would fill a hand-written `[links]` (`up = [...]` only) with
`down`, `same`, `next`, `prev`, `trail` and the rest. With it, saving what was
read changes nothing, and a vault with no `[links]` section stays without
one until a setting really differs. A key already in the file is kept even
when it is set back to the default. The tests in `relations.rs` check the
whole file text.

**Taking effect.** The page saves through `Workspace::set_link_settings`,
which writes vault.toml (a small file; every settings page does this on the
UI thread) and sends the config to the index actor (`set_link_config`). The
actor rebuilds the edges on its own thread, so the UI never walks the vault.
The Links tab never waits for the index: `link_settings()` and the list of
field names the vault uses (cached per index version) use `try_read`.
Until the index has applied it (on a big vault that can take seconds), the
workspace answers `link_settings()` from the config it just saved, so a second
edit never starts from the old one. The vault.toml poll sees the same config
later and finds nothing to do. Hand edits still arrive through that poll.

**What the page edits.** The five name lists (comma separated, first name is
the one Quire writes), implied edges, the trail mode, Dendron (on/off,
delimiter, field), and custom types with a colour. A colour must be `#rrggbb`
or `#rgb`; anything else is refused where it is typed and not saved. The
graph uses a type's colour when it has one (`Graph::type_colors`), and the
app's colour by position otherwise. Any field name is a type already; the
page only needs an entry for a type that has a colour, and offers the types
the vault uses as buttons.

**Cost.** Nothing runs before the first frame. The page reads the config the
index already holds and the field counts it already built.

## 2. The web app (`quire-cli serve`)

`quire_app::links_web` renders three pieces of HTML from the index: the
trail (`trail_html`), "Links by type" (`typed_html`) and the tree
(`hierarchy_html`). The web app puts the trail above a note and the groups
in the note's aside; `/hierarchy` is the tree, linked from the side bar when
the vault has hierarchy edges.

* **One rule for visibility.** Each function takes `href: &dyn Fn(&NotePath)
  -> Option<String>`; a note without a URL doesn't exist for it. The web
  passes `Guard::listed` (hidden folders from `--hide` and `[web] hide`,
  hidden segments, locked folders and `.qenc` names), the same check as
  backlinks, search and the tree. Publishing passes "is a published page".
* **Filtering happens before walking.** `Relations::trails_where` leaves a
  refused note out of the walk, so a trail stops below it instead of
  skipping it; `relations_where` drops edges to refused notes before the
  groups are made, so group headings (including type names) come only from
  visible edges. The hierarchy tree filters children, and a visible child of
  a hidden parent is a top note.
* **Derived edges carry their origin.** An edge made by a Breadcrumbs note (a
  tag, folder or list note, Dendron) records that note, and so does its
  implied reverse. An edge is shown only when both ends and its origin pass
  the visibility function: a hidden list note's neighbour field, its field
  name and the order of its items appear on no visible page, in the web, in
  published sites and in the MCP tools. The Hierarchy link in the side bar
  and the "Hierarchy" page are offered only when a visible note has a visible
  hierarchy edge, so they say nothing about hidden notes.
* **Agent policy.** The web app doesn't use the agent policy (docs/serve.md
  says so), so none is applied here. Where agents see typed links, the
  existing MCP guard is unchanged.
* **Escaping.** Every title, path and field name goes through
  `escape_html`; hrefs are escaped as attributes. No script, no new asset
  beyond a few CSS rules. The CSP is unchanged.
* **Sign-in.** The pages are ordinary routes behind `session()`.
* **`[links] trail`** governs the trail and the "Links by type" block together:
  `off` shows neither, `on` shows both, `auto` shows them when a note the
  reader may see has a hierarchy edge.

**Cost of a rebuild.** Every batch of changes rebuilds the whole link graph
(`LinkGraph::build`, derived edges included). The actor applies the batch under
the write lock, builds the graph under a read lock (searches and the UI
carry on) and installs it under a brief write lock (a pointer swap). Only the
actor writes, so the notes cannot change in between; a reader that comes in
between sees the new notes with the previous graph, which answers nothing for
a path it doesn't know. The build is not incremental: it is linear in notes and
links. Measured by `quire-index/tests/graph_timing.rs` (10,000 notes, 8 links
each, hierarchy and tag fields), in the dev profile on the build machine:
about 0.7 s per build; the install takes microseconds. An optimised build is
several times faster. Incremental updates were left out: derived edges depend on
other notes (a list note changes edges between notes it doesn't contain).

## 3. Published sites

`publish` is now `publish_with(…, TypedLinks)`: `Auto` (default), `On`,
`Off`; `quire-cli publish --typed-links auto|on|off`. With it on, each page
gets the trail before its text and a "Links by type" block after it. Auto
means the vault's trail rule (on when some note has a hierarchy field).

The URL map of published pages is the visibility function, so an unpublished
or excluded note (`publish: false`, not marked, templates, exports) has no
URL and appears nowhere: not in a trail, not in a group, not in the tree.
Typed links in a note's body (`up:: [[Secret]]`) are text the author wrote
and are rendered as before (a link to an unpublished note is plain text, with
the name the author wrote). Only the generated trail and groups are new, and
they name nothing unpublished. Typed links written as front-matter
properties are not part of the page text.

The desktop Publish dialog uses `Auto`; it gets no new control (the dialog is
a shared file). The tests are in `links_web.rs`.

## 4. Breadcrumbs' other edge builders

Chosen: **tag notes, folder notes, list notes and Dendron names.** Why these:
they are the ones in Breadcrumbs' own documentation as explicit builders that
a note says with a property, they need no pattern language, and they cover
the layouts people have (a topic by tag, a folder with an index note, an
outline written as a list, a dotted-name vault). Property names and
behaviour are Breadcrumbs v4's (see the table in the format doc). Where
Quire differs: a tag note without `BC-tag-note-field` uses the first `down`
name (Breadcrumbs needs it); a folder note's recursion is flattened like
Breadcrumbs' (all notes below are children, not nested).

Not done: **Johnny.Decimal, date notes, regex notes** (each needs a
pattern syntax and settings of its own, and their users are far fewer);
**transitive rules** beyond reversal; Dendron's "display trimmed" (a display
option); Breadcrumbs' per-edge-builder global defaults for the neighbour
field.

**How they are built.** `quire_index::derived::derive` runs inside
`LinkGraph::build`, after the links are resolved, and gives `Relations::build`
a second list of `(from, field, to)`. Written edges go first, so a derived edge
equal to a written one is dropped. Derived edges are marked
(`Relation::derived`), are not in the field counts (they are not links in a
note) and are carried through `Relations::merged` for unlocked folders.
Cost: one range lookup per note to see whether it has a `BC-` property;
tag and folder indexes are built only when such a note exists, and a list
note is read from the source the index already holds, at most 5000 items.
The output is sorted, so it doesn't depend on hash order. Nothing runs
before the first frame: the index worker does it with the rest of the
graph.

## 5. Tests

* `relations.rs`: settings round trip with byte identity (unknown keys,
  comments, other sections, defaults not added), colours.
* `derived.rs` and `tests/derived_edges.rs` (with `tests/fixtures/breadcrumbs/`):
  tag (nested, exact), folder (recurse), list (nesting, field before the
  link, neighbour, exclude-index, code blocks), Dendron, order, written wins.
* `links_web.rs`: property test over 40 random vaults, four publish modes:
  no output file names an unpublished note; trails stop below hidden notes;
  escaping.
* `quire-web/tests/web.rs`: property test over random vaults with hidden
  folders: no page names a hidden note; the trail and groups show;
  signed-out requests are refused.
* `layout_check`: Settings → Links is a registered settings tab, so
  `feature_tabs_keep_their_size` and the Settings dialog checks cover it.

## Deferred

* A Publish dialog control for typed links (the CLI has the flag).
* Colours by picker (hex text only).
* A hierarchy page that expands lazily (it is rendered whole, capped at
  3000 notes).

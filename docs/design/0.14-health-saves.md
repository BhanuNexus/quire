# Quire 0.14 health: dropped results become lint errors

Status: current
Area: errors that `let _ =` and `map_err(|_| ..)` used to lose: saves, history snapshots, the agent ledger, sync state, token files
Code: `#![warn(clippy::let_underscore_must_use, clippy::map_err_ignore)]` in `crates/{quire-vault,quire-sync,quire-agent,quire-mcp}/src/lib.rs`; `Vault::tell_once` and `move_history_or_tell` (`crates/quire-vault/src/history.rs`); `AgentStore::keep_version` and `AgentStore::record` (`crates/quire-agent/src/store.rs`)

Plan item 27 of the codebase-health pass. CI runs clippy with `-D warnings`, so the two lints are errors in these four crates. The lints are set in each crate root, because `[lints] workspace = true` can't be combined with crate-specific lints in `Cargo.toml`.

## The rule

A dropped `Result` is one of three things:

- **Passed up** with `?` when the caller can act on it. The version from before a write is always taken this way: no version, no write.
- **Told to the person once** when the change itself stands and failing it would make things worse (reporting a write that happened as failed, or hiding a new recovery key). The vault's history notice (`Vault::take_history_trouble`, shown by `quire-app` as a warning) carries it. `Vault::tell_once` lets crates above the vault use it. The agent store sends the version kept after a write (`keep_version`) and every ledger line (`record`) through it.
- **Kept on purpose** with `#[expect(clippy::let_underscore_must_use, reason = "...")]` on the statement. Examples: a cache, a crash's leftover, a send to a receiver that may be gone, cleanup whose caller already returns the real error, or a counter the next pass makes up for.

A write into a `String` uses `.expect("a String takes any text")`, and gzip into memory uses `.expect(...)` instead of falling back to empty bytes.

`map_err(|_| ..)` is gone where the error said something. Only `VaultError::NotFound` becomes "not found". A cipher error is matched by its type (`aead::Error` has no fields). An `#[expect(clippy::map_err_ignore, ...)]` remains where hiding the cause is the point: a path the agent guard hides, or a sealed MCP request state that fails to open.

## Defects found (each in its own commit, with a test and a changelog bullet)

- A note renamed while its history could not be moved left some old versions under the old name, and nobody was told (`a_rename_whose_history_cant_follow_is_told`).
- Every agent write, and accepting a suggestion for a note that isn't open, reported a note that couldn't be read (held open, no permission) as "doesn't exist" (`a_note_that_cant_be_read_is_not_reported_as_missing`).
- An undo of an agent's change overwrote or trashed the note even when the version from before the undo couldn't be kept (`an_undo_is_not_written_without_the_version_from_before`).
- `/oauth/revoke` answered 200 when the revocation couldn't be saved, so a client forgot a token that still worked (`a_revocation_that_cant_be_saved_is_not_reported_done`).

## Hardening without a dedicated test

- **quire-sync:** `generation_settled` no longer reports a snapshot as settled when the sync folder couldn't be read, so tidying deletes no log files after a failed read. After a key change, the key refresh reads the vault level again and every transport keeps it for sealing; a failed read fails the refresh, and the app's sync session keeps the key news so the next pass tries again. Under the new key the old ways of sealing are refused (`Content::seal_as`), so a stale level stops pushes rather than sealing the old way. S3 and WebDAV kept the level read at the start of the session until 0.13.3 (`RemoteTransport::read_level` now stores it), and a failed refresh was not tried again in the same session (`a_key_refresh_that_fails_is_tried_again_next_pass`, `after_a_key_change_a_remote_device_seals_at_the_vaults_new_level`). Argon2 refusing stored parameters is reported as damaged data, not as a wrong passphrase. A key that won't open for any reason other than the passphrase is no longer reported as "wrong passphrase".
- **quire-vault:** a rescan thread that can't start no longer leaves the watcher's pending flag set, which had stopped all later rescans.
- **quire-agent:** forgetting suggestions under a newly locked folder counts only the archived copies it really removed (`remove_archived` returns its error).

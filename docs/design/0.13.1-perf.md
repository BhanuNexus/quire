# Quire 0.13.1: size, speed and CI time (hardening pass, performance)

Status: done for 0.13.1. Owner: the hardening pass's performance team
(`hard/perf`). No features; persisted formats unchanged.

What this pass measured, what it changed, and what it left. Numbers are
from the 2-core VM the other hardening teams were building on at the same
time (load average 8–10 throughout), so speed numbers are medians of runs
alternated between the old and new builds, with their spread.

## 1. Binary size

The Lite `quire` was 45.4 MiB at 0.13.0 (the release check rounds up: 46),
over the old 45 MiB budget; 0.13 raised the budgets to 50 and 80 MiB.

### How it was measured

As `release.yml` builds (`packaging/linux/package.sh`: `--release
--locked --target x86_64-unknown-linux-gnu`, `-C link-arg=-Wl,--icf=all`),
one binary per build, with symbols kept for `cargo bloat --crates` and the
size taken after `strip --strip-all` (what `strip = true` does at link time).
"Before" is a clean checkout of `5590060` (0.13.0 plus CI changes), built
into the same target folder so both share the dependencies' builds.

### Sizes (Linux x86-64, stripped)

| Binary | 0.13.0 | 0.13.1 | Change | `check-size.sh` budget |
|---|---:|---:|---:|---:|
| `quire` (Lite) | 45.39 MiB (47,592,976 B) | 43.82 MiB (45,948,816 B) | −1.57 MiB | 50 → **46** |
| `quire-cli` (Lite) | 24.81 MiB | 23.96 MiB | −0.85 MiB | |
| `quire` (full) | 72.98 MiB (76,526,608 B) | 71.99 MiB (75,486,992 B) | −0.99 MiB | 80 → **74** |
| `quire-cli` (full) | 52.74 MiB | 51.80 MiB | −0.94 MiB | |

Checked once exactly as the release builds it (both binaries in one
`cargo build`, `strip = true` from the profile): the Lite `quire` is
45,959,736 B and `quire-cli` 25,157,800 B, within 40 KB of the table, and
`check-size.sh` passes (44 MiB against 46, no symbol table).

Packages shrink less, because the fonts were already compressed by the
archives: `quire` + `quire-cli` gzipped (the `.tar.gz`; the AppImage's
squashfs is similar) Lite 28.53 → 27.89 MiB, full 49.84 → 49.12 MiB; with
xz (the `.deb`) Lite 20.81 → 20.67 MiB, full 36.66 → 36.16 MiB.

Sections of the Lite `quire`: `.text` 28.27 → 27.07 MiB, `.rodata` 6.49 →
5.80 MiB; unwind tables and relocations grew a little (`.eh_frame` 3.44 →
3.66 MiB): size-optimised code has more, smaller functions.

The targets were Lite ≤ 43 MiB and full ≤ 70 MiB. Neither was reached
without slowing a hot path; what is left is in §5.

### What the Lite binary is made of (`cargo bloat --crates`, `.text` 28.3 MiB at 0.13.0)

Our crates are about 11.5 MiB of it: quire-app 3.2, the desktop 2.1,
quire-agent 1.3, quire-sync 1.1, quire-import 1.0, quire-mcp 1.0,
quire-index 0.54, quire-markdown 0.40, quire-intel 0.35, quire-vault 0.33,
quire-canvas 0.30, quire-ai 0.26, quire-assistant 0.20. Then std's generic
code (2.4), egui (1.4), D-Bus (zbus 0.67, accesskit_unix 0.38,
secret_service 0.20), two font stacks (skrifa 0.59 + read_fonts 0.40, in
two versions each), PDF text (hayro_syntax 0.35, hayro_interpret 0.29,
moxcms 0.30, jbig2 and JPEG 2000 decoders 0.32), the Excalidraw renderer
(vello_cpu 0.35, fearless_simd 0.35 in two versions), TLS (rustls 0.29,
ring 0.20) and three HTML parsers' tree builders (html5ever in two
versions: ammonia, dom_smoothie and htmd).

The full edition adds Typst (typst_library 2.7 MiB, typst_layout 0.47,
krilla 0.66, wasmi 0.43), Mermaid (1.1), citations (citationberg 0.76,
hayagriva 0.64) and `.rodata` of 15.2 MiB (Unicode and line-break data,
the fonts, the citation styles).

### What changed

1. **Quire Lite's four bundled faces are gzipped** (Inter Regular,
   SemiBold, Italic, JetBrains Mono NL: 1.46 → 0.71 MB). `main` starts a
   thread (`quire-fonts`) that unpacks them while the window opens, so the
   first frame doesn't wait for it; the full edition keeps taking them,
   uncompressed, from quire-typeset (which has no inflate dependency; see
   §5). A test checks each `.gz` against its `.ttf`. −0.75 MiB.
2. **Our cold crates at `opt-level = "z"`** (were `"s"`): quire-mcp,
   -agent, -import, -web, -sync, -assistant, -ai, -plan, -typeset. They
   run once per action; the MCP budgets are checked by the perf job (§2).
3. **MCP tool schemas as JSON text** (`schema!` in quire-mcp): the 55
   literal schemas of the tool list and the resource templates were
   `json!` literals, which expand to code building each value node by
   node (`read::tools_before_canvas` alone was 143 KiB of code). `schema!`
   keeps the literal's text (`stringify!`) and parses it once, when the
   registry is made. The `tools/list` output was compared byte for byte
   over every tool before and after; a test checks `schema!` against
   `json!` on escapes and trailing commas.

2 and 3 were built together: with the fonts (−0.75 MiB) they make the
−1.57 MiB of the Lite app, so the two together saved about 0.8 MiB there
(and about 1 MiB in the full edition, which keeps its fonts); they weren't
measured apart.

### Tried and not kept

* `opt-level = "s"` (from 3) for `similar`, `hayro-syntax`,
  `hayro-interpret`, `hayro-cmap`, `zune-jpeg` and `image-webp`: the Lite
  binary grew by 0.3 MiB, presumably because their generic code is
  compiled in the calling crates anyway and less inlining only added calls.
  Reverted.
* Not tried: `yaml-rust2` without its default `encoding` feature (it brings
  a second `encoding_rs`). Nothing calls its decoder, so LTO should already
  leave it out; the change would be in `[workspace.dependencies]`, the
  dependency team's part.

### Full-edition-only code in Lite

None found. Lite links no Typst, Mermaid, citation, resvg or `hayro`
(page rendering) code; it has `hayro-interpret` and `hayro-syntax` for PDF
text, as designed.

## 2. Speed

### The perf job's budgets, before and after

`packaging/perf-check.py` as the CI job runs it (`--runs 5 --app-runs 5`,
Xvfb), on `--profile perf` builds of the full edition (with
`quire-desktop/bench`), the old and new builds alternated, four rounds each
(a fifth pair, run while a build of this branch's tests was still going,
is left out: it failed the index and typing budgets on both). Medians of the
four rounds' medians, with their range. The script times wall-clock; it has
no CPU-time mode.

| Measure | Budget (fails above) | 0.13.0 | 0.13.1 |
|---|---:|---:|---:|
| Index build, 2,000 notes | 420 (525) ms | 382 (360–396) | 372 (368–374) |
| Search, 2,000 notes (p50) | 10 (12.5) ms | 1.15 (1.10–1.16) | 1.31 (1.25–1.43) |
| Section search (p50 / p95) | 15 (18.8) ms | 6.9 / 11.1 | 7.4 / 12.4 |
| MCP `view`, 10k notes (p50) | 10 (12.5) ms | 0.63 | 0.62 |
| MCP `search`, 10k notes (p95) | 50 (62.5) ms | 25.4 (23.0–26.1) | 25.4 (22.7–28.0) |
| PDF text per page (p50 / worst) | 50 (62.5) ms | 0.29 / 7.7 | 0.33 / 8.1 |
| MCP start to first answer, 200 PDFs | 500 (625) ms | 1.75 | 2.15 |
| … until all 200 PDFs are searchable | reported | 2.0 s | 2.2 s |
| Startup to first frame, 10k notes / empty | 1,500 ms cap | 144 / 138 | 151 / 143 |
| Startup: what 10k notes add | 20 (25) ms | 8.0 (0–11.9) | 4.8 (1.1–8.2) |
| Keystroke → frame while first indexing (p50) | reported | 5.24 | 5.38 |
| Keystroke → frame, jobs on (p50 / p95 / p99) | p95 10 (12.5), p99 16 (20) ms | 5.19 / 7.28 / 10.9 | 5.45 / 7.83 / 11.1 |
| Canvas, 1,000 cards (p50 / worst) | 8 (10) ms | 2.31 / 6.3 | 2.31 / 6.2 |

Every budget holds with the margin it had. The differences are within the
spread except three small, consistent ones, all far inside their budgets:
the MCP server's first answer (+0.4 ms: it now parses its 55 schemas when
it starts, and quire-mcp is size-optimised), BM25 search (+0.15 ms) and
PDF text per page (+0.04 ms). Startup is 6–7 ms later on both vaults in
the medians, with overlapping ranges; the full edition measured here
doesn't unpack fonts. Quire Lite unpacks 1.46 MB of fonts on its own
thread from `main`, before the window exists; it isn't in the perf job.

### The link graph (rebuilt on every index batch)

`IndexService` rebuilt the whole link graph after every batch: every link
resolved again and every backlink's context line copied, also for batches
holding only PDF text. Now (`Index::graph_patchable`,
`LinkGraph::patch`):

* a batch of edits to notes already indexed, with unchanged aliases (so
  every link of the vault resolves as before), removes those notes'
  outgoing links, backlinks and unresolved targets and adds them again;
  derived edges (tag, folder, list and Dendron notes) are made again (one
  pass over the records, no resolution); the typed-link relations and the
  hierarchy are rebuilt only when the edited notes' typed links or the
  derived edges changed;
* a batch of attachment text leaves the graph alone;
* a load, a new or removed note, new aliases or new `[links]` settings
  rebuild it as before.

A randomised test (400 edits over notes with links, typed links, aliases,
tag notes, list notes and Dendron names) checks the patched graph against a
rebuild after every edit. (Notes whose names differ only in case are left
out: which of `A.md` and `a.md` `[[a]]` means depends on map order, in a
rebuild too.)

`tests/graph_timing.rs`, 10,000 notes with 16 links each, debug build:
rebuild 1.7–2.4 s; an edit (parse, store and patch) 20–26 ms.

### Per-frame work that grew with the vault

* **Home**: on a cache miss (after every index batch) it took blocking
  index reads (titles of recent and pinned notes, the agenda, the stats)
  and read its word-count baseline file. It now reads without waiting
  (`Workspace::try_agenda`, a `try_read` guard) and keeps what it showed
  while the index worker writes; the baseline is read once a day; a
  `.base` view's file is read at most once a second (it was read on every
  frame).
* **Sidebar**: the Tags tab gathered every note's tags, the open tag's
  notes, and the Tasks tab every open task, on every frame and under
  blocking reads. They are kept per index version and refreshed without
  waiting. The two-pane browser's previews copied each note's whole text
  to keep 160 characters.
* **Status bar**: read the note count under a blocking read lock every
  frame; `IndexService::note_count` reads an atomic.
* **`quire-cli serve`, Hierarchy page**: it was made again for every
  request under the index read lock, and finding the top notes sorted
  every note's children by title to see whether it had any. Roots are
  found with one pass over each note's edges, and the page's tree is kept
  for the index version and hidden folders it was made for. The page still
  lists at most 3,000 notes: paging it would change what readers see.

Looked at and left: the command palette's note and task lists are made on
each frame while it is open (a fuzzy match over every note; egui repaints
only on input, and caching it needs a key over the recent list and the
settings); the Agenda panel's agenda still uses a blocking read on a cache
miss.

## 3. Memory

Resident memory of the desktop app (`--profile perf`, full edition) with
the CI bench vault (10,000 notes and `Big.md`, 78 MB) open and idle for
90 s, alternated: **0.13.0 700 / 699 MB, 0.13.1 635 / 637 MB** (−63 MB;
an empty vault is 148 MB, so what the vault costs fell from about 552 to
488 MB, −12 %).

What changed:

* The keyword index kept each document's terms as `String`s of their own
  (for removal) beside the same strings as posting keys; the keys are
  `Arc<str>` now and each document's list shares them.
* Each record kept its BM25 term list after the keyword index had taken it.
* The semantic rebuild copied every note's text before cutting passages; it
  now cuts them from the index's own text, 256 notes per short read lock.
  The copy, as big as the vault, was freed but its pages stayed with the
  process.

What is left: every note's text is held three times (the source, its plain
prose in the record, and the passages of the semantic index), and each
record keeps a map of its content words (`NoteRecord::terms`, for tag
suggestions) as `String`s, which by count of strings is probably the
largest part (estimated, not measured: there is no heap profiler here). Sharing them needs an interner across the parser
threads; not done in a hardening pass.

## 4. CI time

CI took about 50 minutes. Changes in `.github/workflows/ci.yml` (all checks
kept; `actionlint` and `zizmor` 1.31.1 clean):

* **Debug and test builds keep line tables only**
  (`CARGO_PROFILE_DEV_DEBUG` / `CARGO_PROFILE_TEST_DEBUG` =
  `line-tables-only`). Panics and backtraces still give file and line; the
  test binaries, their links and the caches shrink.
* **Caches are saved from `main` only** (`save-if` on the three
  `Swatinem/rust-cache` steps, same pinned SHA). Pull requests restore
  `main`'s caches. Seven jobs' caches (lint, four test runners, perf, and
  now test-features) are well over the repository's 10 GB cache limit, so
  every pull request's saves could evict `main`'s and the next run start
  cold (the test job's own timeout notes a cold cache costs 10+ minutes).
* **The Linux runs of other feature sets** (Quire Lite's tests, the PDF
  `render` tests, the agent edit eval) **moved from the end of the
  `ubuntu-latest` test job to their own job, `test-features`**, which runs
  beside the test matrix. Each rebuilt part of the tree with other features
  after the workspace tests had finished. `RELEASING.md` lists the new job
  among the checks to require.

Not done: `cargo-nextest` (not simpler than what is there); sharing build
output between the lint and test jobs (`check` and `build` artifacts don't
mix). The effect on CI time can only be measured on GitHub's runners; the
first runs after merge will show it (expect the first `main` run to be cold).

## 5. Left for later, and for other teams

**Size, for the dependency team** (none of these is a version this pass
could change):

* **Two html5ever versions** (0.38 from `htmd` 0.5.6, the newest release;
  0.40 from `ammonia` and `dom_smoothie`): two copies of the HTML entity
  table (231 KiB each, plus relocations) and of the tree builder. Needs an
  `htmd` on html5ever 0.40.
* **Two font stacks**: `skrifa` 0.42 / `read-fonts` 0.39 (from
  `hayro-interpret` 0.7, kept for Typst) beside 0.44 / 0.41 (epaint, the
  desktop); also `fearless_simd` 0.4 and 1.2 (hayro's JPEG 2000 and JBIG2
  decoders), `hayro-ccitt` 0.3 and 0.4, `miniz_oxide` 0.8 (png) and 0.9
  (the deflate crate), `calloop` / `smithay-client-toolkit` (winit and
  smithay-clipboard).
* `yaml-rust2`'s default `encoding` feature brings `encoding_rs` 0.7 beside
  0.8 (`default-features = false` in `[workspace.dependencies]`; probably
  no size change, see §1).
* **The full edition's fonts**: the same gzip treatment for quire-typeset
  (Inter, JetBrains Mono, STIX Two Math) would save about 0.9 MiB in the
  full edition, but quire-typeset needs an inflate crate as a dependency
  (`miniz_oxide`, already in the tree).

**Size, not done:**

* egui's default fonts (Ubuntu Light and Hack, 0.66 MB) stay: they are the
  fallback for glyphs Inter and JetBrains Mono lack; dropping them changes
  what some text looks like.
* quire-app and the desktop crate at `"z"`: they hold per-frame code, and
  the typing budget (p95 7.8 ms against 10) has little room.
* DT_RELR relocations (would shave 3 MiB) still need glibc 2.36.

**For the QA team:** `vault_sync::tests::one_sync_process_per_vault_and_device`
(quire-app) failed once in this pass's run (`Busy { in_this_process: false }`
at `vault_sync.rs:3017`) on the loaded machine; this pass didn't touch sync.

**CI:** the effect of §4 can only be seen on GitHub's runners.

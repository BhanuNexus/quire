# Quire 0.10: people-facing features

The people workstream of 0.10. It takes back five things 0.9 cut or left
simple (design 0.9 §8.3): Vim macros, marks and Visual-block mode;
reminders while Quire is closed; Markdown in canvas cards; Excalidraw
drawings; and Obsidian Bases formulas and summaries.

## 1. Vim (`quire-text::vim`)

The state machine stays pure and table-tested: the same keys on the same
text give the same outcome. The table (`testdata/vim/cases.tsv`) now has
695 cases recorded from Vim 9.1 by `record.py`, 118 of them new.

### Macros (`vim/macros.rs`)

* `q{reg}` starts recording, `q` stops (in Normal or Visual mode). `qA`
  appends to `a`. The status bar shows `recording @a`.
* Keys are kept as text in the register, as Vim does: Escape is `^[`,
  Enter `^M`, Ctrl keys their control characters, arrows and Delete
  private-use characters. So `"ap` shows a macro and `"ayy` then `@a` runs
  an edited one; a yanked line's break runs as Ctrl-J (down).
* Text the editor types itself in Insert mode reaches the recording through
  `VimState::typed` (the adapter calls it for text and IME commits).
* `@{reg}`, `@@` and counts (`3@a`). A run works on a copy of the note:
  each key goes through `handle`, Insert-mode keys are typed at every
  cursor, and undo inside the macro uses a local history. The note then
  gets the difference as **one edit: one undo step for the whole run**.
* A failing command stops the run, as in Vim (a motion that can't move,
  `w` at the end, a mark that isn't set, a search with no match, `:s` with
  no match), so `100@a` stops at the end of the list.
* Limits: macros nest at most 20 deep and a run stops after 200,000 keys
  ("The macro was stopped: too many keys"). `"+` can't be put inside a
  macro (the clipboard is read asynchronously).
* `:s` inside a macro goes through `Host::substitute` (regular expressions
  in the app, plain text in the tests).

### Marks (`vim/marks.rs`)

* `m{a-z}`, `` `a `` (exact, charwise), `'a` (line, first non-blank),
  `''` and ``` `` ``` (before the latest jump), `` `. `` and `'.` (last
  change), and `'a,'b` ranges on the command line. Jumps are `G`, `gg`,
  `/`, `?`, `n`, `N`, `%`, `{`, `}`, `:{n}` and mark jumps.
* A mark is a line and a column. It moves with its line when lines are
  added or removed above it and goes when its line is deleted (`E20: Mark
  not set`); edits inside the line leave the column, as in Vim.
* Every edit moves the marks: the state machine's own edits with their
  exact span; anything else (typing, undo, edits from other features) by
  comparing the text with the last text it saw, at the next key. A pure
  insertion or deletion is aligned to a line start where it can be.
* `'.` follows Vim: the start of the change, the first line of a linewise
  delete, the line of a linewise put, the cursor after Escape for typing.
* Marks are per note. `NavState` keeps the marks of open notes that aren't
  active, and `session.json` keeps `a`–`z` and `.` with each note's
  position (`positions[path].marks`), so they survive a restart.

### Visual-block mode (`vim/block.rs`)

* `Ctrl-v` in Normal and Visual mode; `v`, `V` and `Ctrl-v` switch between
  the three Visual modes. The system takes Ctrl+V as paste before Quire
  sees it, so in Normal and Visual mode a paste starts block mode (`"+p`
  still pastes). With an empty clipboard nothing reaches Quire, and Vim's
  other key, `Ctrl-q`, quits the app (the state machine still accepts it).
* A block is lines and **display columns**: a tab reaches the next tab
  stop (`tabstop`, 8 as in Vim), wide characters (CJK) take two columns
  (`unicode-width`). A char the block's edge cuts through is split into
  spaces when the block is edited, as Vim does.
* Shown with the editor's multi-cursor: the cursor's row is the main
  selection and the other rows are extra selections (`Outcome::extra`).
* `d`/`x`, `y`, `c`, `I`, `A`, `$` (to each line's end), `D`, `C`, `r`,
  `~`, `u`, `U`, `p`/`P` (a one-line register goes on every row), `J`,
  `o`, `O`, `>`, `gv`, `.`. `X`, `Y`, `S`, `R` and `<` act on whole lines.
* `I` and `A` skip lines that end before the block (a line ending exactly
  where the block starts gets the text); `A` pads short lines with spaces;
  `$A` appends at each line's end. They type at one cursor a row, live,
  through the editor's own multi-cursor typing, and Escape makes it one
  undo step and puts the cursor where Vim does.
* A yanked block is a block register: `p` puts row `i` on the `i`-th line
  from the cursor, padding short lines and adding lines at the end.
* Deliberate difference: Vim inserts a block's text on the other rows only
  at Escape; Quire types on all rows as you go (the multi-cursor), so an
  Enter typed during a block insert goes to every row.

Settings → Editing lists what is supported; not supported: a vimrc,
`:normal`, Ctrl-A and Ctrl-X.

## 2. Reminders while Quire is closed (`quire-app::remind_bg`, `quire-cli remind`)

* `quire-cli remind <vault>` reads the vault's reminders (only notes that
  contain `⏰` or `[remind::` are parsed, so it is quick enough every
  minute), shows each due one as a desktop notification (`notify-rust`)
  and records it in `<config>/reminders/<vault key>.json` (device-local,
  forgotten after 30 days). The vault key is a stable FNV hash of the
  canonical path.
* The app checks the same file before it fires a reminder and records the
  ones it fires, so each reminder shows once on the device whichever shows
  it. Missed reminders are still listed when Quire starts, as before.
* The first run only takes note of what is already due, so turning the job
  on doesn't bring up a week of old reminders.
* **Settings → Planning → "Remind me even when Quire is closed"** installs a
  per-user job that runs `quire-cli remind <vault>` every minute. No
  administrator rights. The setting shows the files and commands before
  and after, and turning it off removes exactly those.

  | System | What is installed |
  |---|---|
  | Linux with `systemd --user` | `~/.config/systemd/user/quire-remind-<key>.service` and `.timer` (`OnCalendar=*-*-* *:*:00`), then `systemctl --user daemon-reload` and `enable --now` |
  | Linux without it | a crontab line ending `# quire-remind <key>` (with `DBUS_SESSION_BUS_ADDRESS` for notifications) |
  | macOS | `~/Library/LaunchAgents/dev.quire.remind.<key>.plist` (`StartInterval` 60), `launchctl bootstrap gui/<uid>` |
  | Windows | `schtasks /Create /SC MINUTE /MO 1 /TN "Quire Remind <key>"` |

* `quire-cli remind <vault> --install | --uninstall | --status` does the
  same from a terminal; `--dry-run` lists what would show.
* Paths are quoted for each system: systemd doubles `%` and `$`; cron uses
  single quotes and escapes `%`; launchd plists escape XML.
* The job gets the session's `TZ` when Quire runs with one (systemd
  `Environment=`, a `TZ=` prefix in cron), because cron and systemd use the
  system's zone: a reminder at 09:00 must be 09:00 for both.
* Tested: file and command construction for all four (unit tests); the
  fired list and first-run behaviour; on Linux in a container without
  `systemd --user`, the cron path for real: Settings installed and removed
  the crontab line, and the cron daemon ran `quire-cli remind`, which
  recorded a reminder at its minute. The systemd, launchd and Task
  Scheduler paths are covered by the unit tests only.

## 3. Canvas text cards use the preview renderer

* Text cards are drawn by `egui_commonmark`, the note preview's renderer
  (callouts, tables, task lists, code, links), after the same
  `for_preview` step (wikilinks, embeds).
* Each card is laid out once per (text, width, zoom, theme) on a layer of
  its own, and its shapes are kept; later frames only move them (text keeps
  its laid-out galley, so moving is cheap). Panning never lays out again.
* Not rendered in cards: math (stays as its source); a card that is only a
  Mermaid diagram still draws the diagram. Links in cards aren't clickable
  (double-click edits the card, as before).
* The 1,000-card frame test still passes with the same bound.

## 4. Excalidraw drawings (`quire-canvas::excalidraw`, desktop `drawing_ui`)

* Reads `.excalidraw` (JSON) and `.excalidraw.md` (the Obsidian plugin's
  format: `## Drawing` with ```` ```json ```` or ```` ```compressed-json ````,
  LZ-string base64, line breaks ignored; pictures from `## Embedded
  Files`). Deleted elements are skipped.
* Draws rectangle (rounded when `roundness` is set), ellipse, diamond,
  line, arrow (arrow, triangle, bar, dot and circle heads), freedraw, text
  (alignment, line height, rotation), image (`files` data URLs, or vault
  files) and frames (with their names), with stroke styles, opacity and
  angle. Clean style: no hand-drawn wobble; hachure and cross-hatch fills
  are drawn flat and lighter.
* One list of draw ops feeds two outputs: SVG (`to_svg`, for HTML export)
  and pixels (`drawing_ui::render`, with `vello_cpu` and font outlines from
  `skrifa`, both already compiled into egui, so no new crates are built).
* Where: `![[Plan.excalidraw]]` in the editor and the preview, file cards
  on a canvas, the drawing note itself (a banner with the picture), a
  `.excalidraw` file (a surface), and HTML export (an SVG `data:` image).
  Pictures are cached by the file's content.
* A drawing changed elsewhere: its own note (the banner) and the
  `.excalidraw` surface redraw when the file's modified time changes;
  embeds in other notes, the preview and canvas cards keep egui's cached
  texture until Quire restarts (egui caches textures by URI and doesn't
  ask the loader again).
* Read-only. The notice says: "Excalidraw drawing, shown as a picture.
  Quire doesn't edit drawings: edit in Excalidraw."
* Fixtures are our own small drawings made with the documented format,
  compressed with lz-string 1.5.0 (`testdata/excalidraw/`).

## 5. Obsidian Bases formulas and summaries (`quire-import::obsidian::expr`, `quire-app::bases`)

* **Expressions** (`expr.rs`): a small parser and evaluator, no scripting.
  Literals, lists, `+ - * / %`, comparisons, `&& || !`, `a.b`, `a[b]`,
  `note["my prop"]`, `formula.x` (other formulas; a formula that uses
  itself is an error), `file.*` (`name`, `basename`, `path`, `folder`,
  `ext`, `size`, `ctime`, `mtime`, `tags`, `links`, and `hasTag`,
  `inFolder`, `hasLink`, `hasProperty`).
* Functions: `if`, `date`, `now`, `today`, `duration`, `number`, `min`,
  `max`, `list`, `string`, `link`. Methods: strings (`contains`,
  `containsAll`, `containsAny`, `startsWith`, `endsWith`, `lower`,
  `upper`, `title`, `trim`, `replace`, `repeat`, `reverse`, `slice`,
  `split`, `length`), numbers (`abs`, `ceil`, `floor`, `round`, `toFixed`),
  dates (`year` … `second`, `date`, `time`, `format` with Moment tokens,
  `relative`), durations (`days`, `hours`, `minutes`, `seconds`,
  `milliseconds`), lists (`contains*`, `join`, `sort`, `unique`, `flat`,
  `reverse`, `slice`, `length`, `filter`, `map`, `reduce`, `sum`, `mean`,
  `min`, `max`, `median`), and `isEmpty`, `isTruthy`, `isType`, `toString`
  on everything.
* Dates: `date - date` is a duration; `date + "7d"` / `"1 week"` /
  `duration("2h")`; whole months and years move by the calendar (Jan 31 +
  1M = Feb 28). Front-matter values are read as numbers, yes/no and dates
  when they look like them.
* Anything else is an error shown **in the cell**: "“image()” isn't
  supported".
* **Summaries**: `Average`, `Min`, `Max`, `Sum`, `Range`, `Median`,
  `Stddev`, `Earliest`, `Latest`, `Checked`, `Unchecked`, `Empty`,
  `Filled`, `Unique`, and the base's own (`summaries: { mean3:
  'values.mean().round(3)' }`). A row under the table; a line under cards.
* **Filters**: what a `quire-view` spec can say still goes into the spec.
  When a view's filter needs more (`not`, functions, dates, formulas, or
  folders and tags combined with `and`), the whole filter becomes one
  expression checked note by note, and the limit applies after it. Sorting
  by a formula or `file.*` field is done the same way.
* The base surface caches the worked-out table per (index version, file,
  view, minute).
* Not supported: `groupBy`, map and list views, `this`, `image`, `icon`,
  `html`, regular expressions. `file.ctime` is the last change (Quire
  keeps no creation time); `file.size` counts characters.

## 6. Tests

* `quire-text`: the Vim table (695 cases) and unit tests for macros
  (one undo step, recording status, runaway macros), marks across notes
  and blocks.
* `quire-import`: expression arithmetic, functions, dates, errors and
  summaries; Bases fixtures following Obsidian's documented syntax.
* `quire-app`: a base over a vault (formulas, sorting by a formula,
  expression filters, summaries); reminder job files and commands for all
  four systems, crontab edits, the fired list; drawing export.
* `quire-canvas`: every element type, compressed and plain notes,
  lz-string against the reference library's output, SVG.
* `quire-desktop`: block mode and macros in the real editor; drawing
  pictures (colours where the shapes are); the 1,000-card canvas.
